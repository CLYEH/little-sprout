## 來源

[LS-138](https://linear.app/little-sprout-app/issue/LS-138/iosrelease-組態編譯失敗41-errorpreview-引用-debug-only-mock-無法)（Release 組態 41 error 無法 Archive，pre-existing 自 `#Preview` 引 DEBUG-only mock 起）——CI 只跑 Debug 組態，Release 編譯壞了沒有任何機械信號，直到 [LS-130](https://linear.app/little-sprout-app/issue/LS-130/taskls-20-ios-列表詳情改讀-thumb-pathnull-退回原圖全尺寸只在放大播放時簽) merge-review R2 手動跑 Release build 才發現。前饋必有反饋：修完 [LS-138](https://linear.app/little-sprout-app/issue/LS-138/iosrelease-組態編譯失敗41-errorpreview-引用-debug-only-mock-無法) 後必須有 gate 防回歸。

## 範圍

1. `.github/workflows/ci.yml` `ci` job 加一步（或獨立 job `release-build`）：`xcodebuild -project LittleSprout.xcodeproj -scheme LittleSprout -configuration Release -destination 'generic/platform=iOS Simulator' build`（只 build 不測試；沿用既有 derivedData／cache 設定；簽章用 `CODE_SIGNING_ALLOWED=NO`）。觸發條件沿用 [LS-137](https://linear.app/little-sprout-app/issue/LS-137/harnessci-點擊目標-gate-路徑過濾漏掉-featuresdesignsystem-之外的-swiftui-viewls-136) `ui-test-trigger.sh`（動到 `LittleSprout/**/*.swift` 才跑）或無條件跑——handoff 說明取捨。
2. 自測：負控樣本（模擬一個 `#Preview` 引 DEBUG helper 且未包 `#if DEBUG` 的暫時檔 → Release 紅）在 PR body 附實跑輸出；`.test.sh` 若可行（純腳本判定部分）補案例。
3. `docs/COLLABORATION.md` §7 對照表加一列。

## 不做

不改 Swift 程式碼（[LS-138](https://linear.app/little-sprout-app/issue/LS-138/iosrelease-組態編譯失敗41-errorpreview-引用-debug-only-mock-無法) 負責）；不動 Debug 測試流程。
