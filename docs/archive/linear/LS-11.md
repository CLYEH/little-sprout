## 描述

來源：[LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies) handoff 指出的 gate 缺口。CI 的 migration rules 目前只驗「supabase/tests/ 有沒有變更」，測試內容不會被執行——依 CLAUDE.md 最高原則「前饋必有反饋」，RLS 測試必須有機械執行層。

## Scope

* `.github/workflows/ci.yml` 加一個 ubuntu job：偵測到 `supabase/` 存在（或變更）時，起 Supabase local stack（supabase CLI＋Docker）→ `supabase db reset` 套 migration → `bash supabase/tests/run.sh`，任一失敗即紅燈。
* 設為第四個 required status check（同步更新三條保護分支與 docs/COLLABORATION.md §2、§7）。
* 順帶：docs/COLLABORATION.md §5 補記開票結構規約（Project＝epic／Milestone＝feature 群／Issue＝story 帶驗收條件／Sub-issue＝task，僅多 agent 接力的 story 才拆）。

## 驗收條件

- [ ] 紅綠驗證：刻意弄壞一條 RLS policy 的 PR 會被此 job 擋下（紅燈證據），修復後轉綠
- [ ] docs/COLLABORATION.md §7「migration 必附 RLS 測試」列從「✅ 弱」升級並更新敘述
- [ ] 三條保護分支 required checks 更新

備註：harness 票，依 §2 例外走 hotfix 流程。依賴：[LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-%E5%B0%88%E6%A1%88schema-migrationrls-policies) 併入（要有 migrations／tests 才能紅綠驗證）。
補充（[LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies) 修復輪遗留）：驗證用的 PG16 stub bootstrap／reset／mutation 腳本目前在 scratchpad 未進 repo——本票實作時一併決定：若 CI 用 supabase CLI local stack 則不需要；若 Docker 環境不可靠，把 stub 腳本收進 supabase/tests/ 作為備援執行路徑（QA 也能原樣重跑）。
