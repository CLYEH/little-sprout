## 來源

[LS-143](https://linear.app/little-sprout-app/issue/LS-143/taskls-24-後端-刪除帳號-rpc唯一-owner-須先轉移成員內容軟刪併發無死鎖)（`delete_my_account()` RPC，PR #244）merge-review R1（`d9cce6a4`）i1 與 [LS-143](https://linear.app/little-sprout-app/issue/LS-143/taskls-24-後端-刪除帳號-rpc唯一-owner-須先轉移成員內容軟刪併發無死鎖) 票文「規格分歧與取捨 a)」——RPC 只做資料面、標記 `profiles.deletion_requested_at`，`auth.users` 的實際刪除交由本票的 Edge Function（service_role）完成。

## 背景（R1 i1 實測）

`delete_my_account()` 回傳成功之後、這支 Edge Function 真正刪掉 `auth.users` 之前，帳號仍是完全可用的登入身份——`deletion_requested_at` 目前不被任何 RLS policy 或 grant 讀取，同一個 `authenticated` 身分可以立即建立新家庭並成為新家庭 owner、上傳照片等。若使用者在這個過渡窗口內又成為某個家庭的唯一 owner，之後 `service_role` 執行 `delete from auth.users` 的 cascade（`auth.users` → `profiles` → `family_members`）會觸發既有的 `private.enforce_family_has_owner()` trigger 而 `raise LS001`，本 Edge Function 的刪除會失敗（PLAUSIBLE，R1 未能實測，見 [LS-143](https://linear.app/little-sprout-app/issue/LS-143/taskls-24-後端-刪除帳號-rpc唯一-owner-須先轉移成員內容軟刪併發無死鎖) PR #244 review 全文）。

## 範圍

1. `supabase/functions/delete-account`（新的部署單元，repo 目前沒有任何 `supabase/functions/*`，這是第一個）：
   * 以 `service_role` 呼叫 GoTrue admin API 刪除呼叫者對應的 `auth.users` 列（`profiles` 對 `auth.users` 是 `on delete cascade`，屆時 `profiles` 列會跟著消失）。
   * **驗收條件必須涵蓋**：刪除前重跑一次資料面清理（比照 `delete_my_account()` 的邏輯，`service_role` 身分），或改用「`deletion_requested_at is not null` 時以 RLS 擋下寫入」把過渡期的破壞性動作（例如建立新家庭、成為新 owner）直接擋掉——兩者擇一並在 PR 說明取捨。
   * 驗證「使用者在過渡期又成為某家庭唯一 owner」情境下，刪除仍能成功完成（不能因為 `LS001` 而失敗；若採 RLS 擋寫方案，這個情境從一開始就不會發生，等同解決）。
2. **client 端契約**（已在 `docs/API.md` §4 `delete_my_account` 明文，本票落地）：`delete_my_account()` RPC 回傳後，client 必須**立即**呼叫這支 Edge Function，中間不得允許使用者做任何操作。
3. **Apple Sign-in 授權撤銷**（2026-09-03 orchestrator 補，來源 [LS-132](https://linear.app/little-sprout-app/issue/LS-132/法務內容隱私權政策與使用條款正式文本繁中含-ugc-零容忍條款同步公開網址供-app-store) 隱私政策 §8 承諾）：刪 `auth.users` 前對 Apple 呼叫 token revoke 端點（`https://appleid.apple.com/auth/revoke`，需 Sign in with Apple client secret／[LS-8](https://linear.app/little-sprout-app/issue/LS-8/phase-0-4註冊-apple-developer-program個人佔-bundle-id-與-app-名稱) 付費帳號到位後才可實測）；Google 登入若有 refresh token 同理；本機無法實測時以 stub 驗流程並在 handoff 明列「待 [LS-8](https://linear.app/little-sprout-app/issue/LS-8/phase-0-4註冊-apple-developer-program個人佔-bundle-id-與-app-名稱) 後真機驗」。若判定不可行則通知 orchestrator 刪除隱私政策該句。

### M2（major）Apple／Google revoke 的 fetch 沒有逾時上限——會擋下刪除

`supabase/functions/delete-account/handler.ts:115-123`（Apple）、`:152-158`（Google）：`deps.fetchImpl(...)` 沒有帶 `AbortSignal.timeout()`。Deno 的 `fetch` 預設**沒有逾時**。
