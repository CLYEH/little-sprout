### minor 1 — `scripts/gates/approval-comment-check.sh:122`：`pipefail` × SIGPIPE 讓「超大 owner comment 且標記在前段」被誤判成未核可

```

```
腳本第 28 行 `set -uo pipefail`；gate 端 `grep -qE`（`destructive-approval-check.sh` 與 `migration-immutable-check.sh:137` 傳的 `grep -qE "$marker_re"`）命中第一行就退出，body 大於 pipe 容量（Linux／macOS 皆 64 KiB）時 `printf` 收到 SIGPIPE 回 141，`pipefail` 把「grep 命中（0）」的 pipeline 判成非 0 → 該則被當成未命中。

**觸發情境**：GitHub 單則 comment 上限 65,536 **字元**，中文 3 bytes/字元 → 實際可達約 190 KB。使用者第一行蓋 `DESTRUCTIVE-APPROVED`、下面貼一大段 migration diff／CI log／中文說明，就會落在這個區間；症狀是「我明明蓋了章 CI 還是紅」，且錯誤訊息說「無一則命中」誤導使用者去改標記格式。方向是 fail closed（不會誤放行），故非 blocker。

**建議修法**：不用 pipe，改檔案重導（順帶也讓「不讀 stdin 的 gate 命令」語意正確）：

printf '%s' "$body" > "$work/body"
