## 來源

[LS-62](https://linear.app/little-sprout-app/issue/LS-62/ios-測試n1-離線快取測試改為計數-stub-呼叫次數去除對-sdk-重試常數的寫死依賴) PR #120 review F5（2026-08-25）。ios-dev 回報 20+ 連跑中 2/24 次 XCTest runner「Early unexpected exit／Restarting after unexpected exit」；reviewer 在專屬模擬器上 6 次 `xcodebuild test`（load ≈ 64）零 crash，判定為環境：`scripts/gates/detect-simulator.sh` 輸出 `platform=iOS Simulator,name=<機型>,OS=<版本>`——**用機型名而非 UDID**，多 agent 併行時全部解析到清單第一台，併發 `xcodebuild test` 打同一顆 sim（現場 3 台 Booted）。[LS-56](https://linear.app/little-sprout-app/issue/LS-56/harnesserror-codes-check-抽取規則硬化註解掉的-case表格首欄格式artifact-retention) 記的「SPM 瞬斷」與 [LS-76](https://linear.app/little-sprout-app/issue/LS-76/harnesspush-gate-對無-swift專案檔變更的-pr-跳過-xcodebuild-test純文件-harness-pr) 記的 `FBSOpenApplicationServiceErrorDomain Code=4` 可能同源。

## 修法

1. `detect-simulator.sh` 輸出 `id=<UDID>`；選擇邏輯：優先找「本 worktree 專屬」模擬器（名稱含 worktree 目錄名，如 `LS-62-iPhone17Pro`，不存在則 `simctl create` 一台，用完不刪、由巡檢清理 >7 天未用者），找不到才退回共用並經 lock（比照 [LS-70](https://linear.app/little-sprout-app/issue/LS-70/harness並行後端票搶同一個本機-supabase-容器db-reset-互踩-隔離或序列化) `supabase-lock.sh` 的 mkdir lock，鍵＝UDID）。
2. push-gate／CI 的 `-destination` 改吃該輸出；CI（單一 runner）維持原邏輯。
3. 正負自測：兩個 worktree 同時跑 → 各自 UDID 不同；強制共用時第二個等 lock。
4. §7 加列；COLLABORATION §4 push gate 敘述同步。

## 驗收

兩 worktree 同時 `xcodebuild test` 皆綠且 UDID 不同；`xcrun simctl list | grep Booted` 可見兩台；[LS-56](https://linear.app/little-sprout-app/issue/LS-56/harnesserror-codes-check-抽取規則硬化註解掉的-case表格首欄格式artifact-retention) 的 10 秒重試保留。
