## 描述

## 來源

使用者 2026-08-25：「巡檢只限這個 session？新 session 會自己記得啟動嗎？是否設 SessionStart hook 檢查；這個 session 的工作慣例有沒有換 session 就忘的？強化 harness。」

## 現況

* 巡檢＝`CronCreate`（session-only、7 天到期）＋ scratchpad `patrol.sh`（隨 session 消失）；新 session 只靠記憶檔提醒（軟）。
* 本 session 才形成、尚未進 repo 的慣例：派工 prompt 五條（暫存檔帶票號／PR body gate／`${name}`／分段落地／informational 處置）、production `db push` 每次需使用者當次授權、並行 harness PR 合併順序（後併者解 §7／ci.yml 衝突）、harness PR 併入 main 後**先** `git pull` **主 checkout 再派 agent**（agent 定義讀自主 checkout）、reviewer informational 必須在 handoff 有處置、設計輪次規則（[LS-68](https://linear.app/little-sprout-app/issue/LS-68/harness設計流程規則機械化-聚焦輪條款收工溢出掃描必跑分段落地掃描收據-gate) 另票）、本機 Supabase 容器互踩（[LS-70](https://linear.app/little-sprout-app/issue/LS-70/harness並行後端票搶同一個本機-supabase-容器db-reset-互踩-隔離或序列化) 另票）。

## 做法

1. `scripts/ops/patrol.sh` 進 repo（從 scratchpad 版移植：open PR mergeState／review／閒置、三分支落後、worktree local vs remote／未 push／dirty 停滯、主 checkout 是否落後 origin/main）＋`--json` 輸出＋自測（合成 repo）。
2. `.claude/settings.json`（專案層，入版控）加 **SessionStart hook**：`git fetch`＋跑 `patrol.sh`，以 `hookSpecificOutput.additionalContext` 注入「巡檢結果＋若本 session 尚未建巡檢 cron，立即 `CronCreate */26 * * * *`（prompt 模板見 COLLABORATION §4-b）」；主 checkout 落後 origin/main 時提示先 pull。依 update-config skill 流程 pipe-test、`jq -e` 驗證。
3. `docs/COLLABORATION.md`：新增 §4-b「Orchestrator 巡檢與 session 連續性」（cron 模板、patrol 用法、三種停滯型態）；§3 補「派工 prompt 五條」；§2 補「harness PR 併入後先 pull 主 checkout」「並行 harness PR 後併者解衝突」；§6 補「production `db push` 每次需使用者當次授權（auto-mode 會擋，不繞）」；§7 加列（SessionStart 巡檢 ✅ hook）。
4. `CLAUDE.md`「每個 agent 都要遵守」補「handoff 未完成欄必列 reviewer 全部 informational 的處置」；`.claude/agents/ios-dev.md` handoff 模板同步。
5. `.gitignore` 加 `.claude/memory/`（harness 鏡像的記憶目錄，不入版控）。

## 驗收

* 新 session 啟動時 context 出現巡檢摘要與 cron 建立指示（hook pipe-test 證據）。
* `patrol.sh` 自測正負；§7 加列。
* 不動 push-gate／CI rules 既有 step。
