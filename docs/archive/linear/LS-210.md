## Findings

**m1（minor，測試韌性）`LittleSproutUITests/SettingsViewTests.swift:106`、`SettingsViewIPadTests.swift:154`**：`XCTAssertFalse(closeButton.waitForExistence(timeout: 3))` 用「等存在」的 API 斷言「不存在」——元素還在時 `waitForExistence` 立刻回 true，`timeout: 3` 實際給的是 **0 秒**寬限，不會等關閉動畫。失敗情境：慢機／CI 上 `tap()` 回傳（等 app idle）後 dismiss 動畫仍在收尾 → 假紅，且錯誤訊息會誤導成「sheet 沒關掉」。建議改 `waitForNonExistence(timeout: 3)`（Xcode 15+）。**不擋**：沿用 `LegalDocumentSheetUITests.swift:29` 既有寫法（Rule 10），且本機 4 次、CI 2 次皆穩；要改建議三處一起改。

**m2（minor，證據對帳）handoff 與 PR body 的 mutation A「斷言原文」與 head 對不上**：申報的 `SettingsViewTests.swift:97「Footer 關閉鈕應可見（safeAreaInset 釘底）」` 這條訊息在 head 的兩支新測試裡**根本不存在**（那是 `LegalDocumentSheetUITests.swift:26` 的訊息），`:118`／`IPadTests:150` 的行號也與 head 的 `:119`／`:148` 對不上——顯示 mutation A 的輸出是最終 commit 前某一版跑出來的。我照申報自己重放：三支確實全紅、且都是真斷言失敗，**實質成立**，故不列 major（LS-209 判準：重放仍綠或紅在 crash／build fail 才是 major）。mutation B 則完全對得上。處置建議：mutation 證據一律在最終 head 上重跑一次再抄進 handoff／PR body。
