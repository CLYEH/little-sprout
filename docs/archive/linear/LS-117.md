## 問題（三個相關缺陷）

1. **placeholder autosave 漂移擋切檔**：Pen 每次切回主 checkout `design/littlesprout.pen` 後，會在該檔累積一個 `placeholder` 屬性的 autosave 漂移（節點總數不變、只有某節點如 `iq3Ic` 的 placeholder 變更）。`pen-open.sh` 的 `pen-land.sh --dry-run` 偵測到此差異就拒絕自動 quit 切檔——但主 checkout 是**保護分支、本就不該被編輯**，這類 UI 態漂移應可安全捨棄。實測主 checkout 的 .pen `git status` 全程 clean（漂移只在 Pen 記憶體／backup、未進 git）。
2. **Pen 無回應時無強制路徑**：漂移造成 Pen quit 時彈「儲存變更？」對話框，osascript quit 回 `-128 User canceled`、SIGTERM 亦無反應，`pen-open.sh` 依規約不送 SIGKILL → 無路可走。需一條**可稽核的強制路徑**（例如：確認目標檔 git-clean＋backup≡落地檔後才允許 SIGKILL）。
3. `check_root_safe` **誤判**：把「主 checkout 查無 Pen backup」誤判為「無法確認安全」，實際是「從未編輯」的安全訊號。

## 修法方向

* placeholder 類「僅 UI 態、節點總數不變、git-clean」的漂移列入可安全捨棄白名單，不擋切檔。
* 加強制 quit 路徑：目標檔 git-clean 且無實質結構 diff 時，TERM 無效可 escalate SIGKILL，並印稽核行（捨棄了什麼、為何安全）。
* `check_root_safe`：查無 backup＝安全（從未編輯），非「無法確認」。

## 相關情資（同批，隨修驗證）
