來源：[LS-33](https://linear.app/little-sprout-app/issue/LS-33/taskls-18-後端-邀請加入申請與審核的-schemarpcrls)/[LS-12](https://linear.app/little-sprout-app/issue/LS-12/決策swift-語言模式5-vs-6-strict-concurrency)/[LS-34](https://linear.app/little-sprout-app/issue/LS-34/harnessrunsh-全形括號在-bash-32-的-unbound-variable-bug-3) 批次收尾的 dead-code-sweeper 觀察項（非該批引入、既有債）。

`supabase/migrations/20260822120200_rls_policies.sql:177` 的 `invites_insert` policy（`with check (family_id in (select private.owned_family_ids()))`）讓 owner 可繞過 `create_invite` RPC **直接對 invites 表 INSERT**——跳過 RPC 內建的 30 天期限上限、1-20 次數上限、邀請碼字元集正規化（UUID bytes {0-5,7,9} 40-bit 熵）。且 :173 的前瞻註解「以邀請碼加入家庭需要 SECURITY DEFINER RPC，見 Phase 1-2」已過時（[LS-33](https://linear.app/little-sprout-app/issue/LS-33/taskls-18-後端-邀請加入申請與審核的-schemarpcrls) 已落地）未收斂。

修法方向（比照 [LS-33](https://linear.app/little-sprout-app/issue/LS-33/taskls-18-後端-邀請加入申請與審核的-schemarpcrls) 對 family_members 的收斂前例）：drop `invites_insert` policy（或改 `with check (false)`），唯一寫入路徑改 create_invite RPC；同步收斂 UPDATE/DELETE 面（owner 撤銷邀請是否走 RPC 一併裁量）；80_ 補攻擊探針測試（owner 直接 INSERT 超長效期邀請 → 42501）。注意：drop policy 會觸發 CI 破壞性偵測器 → 需使用者本人 `DESTRUCTIVE-APPROVED`（規約 §6），開工前先向使用者取得核可。正常 feature 流程；merge 後照 §6 部署 cloud。
