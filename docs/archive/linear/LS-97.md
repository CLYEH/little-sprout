## 描述

## 為什麼從 [LS-39](https://linear.app/little-sprout-app/issue/LS-39/authgoogle-登入supabase-providerios-整合) 拆出來

[LS-39](https://linear.app/little-sprout-app/issue/LS-39/authgoogle-登入supabase-providerios-整合)（lane:ui）的 scope 第 1 項「Supabase Auth 啟用 Google provider」其實不是 UI 工作：Google 登入要一組 **OAuth client**（client ID＋client secret），只能在 **Google Cloud Console** 用你的 Google 帳號建立；secret 要填進 Supabase dashboard 的 Auth → Providers → Google。這兩步 orchestrator／agent 都做不了（需要你的 Google 帳號登入；secret 也不能經過 repo 或對話）。拆成本票（使用者操作、`lane:product`）擋住 [LS-39](https://linear.app/little-sprout-app/issue/LS-39/authgoogle-登入supabase-providerios-整合)，[LS-39](https://linear.app/little-sprout-app/issue/LS-39/authgoogle-登入supabase-providerios-整合) 回到純 iOS 整合。

## 你要做的（約 10 分鐘）

1. Google Cloud Console → 建（或選）一個專案 → APIs & Services → OAuth consent screen（External，app 名稱「萌芽日記」，測試階段可留 Testing）。
2. Credentials → Create OAuth client ID → **Web application**（Supabase 用這種）：Authorized redirect URI 填 Supabase 專案的 `https://<project-ref>.supabase.co/auth/v1/callback`（project-ref 見 Supabase dashboard）。
3. 把 client ID／secret 貼進 Supabase dashboard → Authentication → Providers → Google → Enable。**secret 不要貼進 Linear／repo／對話**。
4. （若 iOS 端要用 Google Sign-In SDK 原生按鈕）再建一個 **iOS** 類型 client（bundle ID 同 app）——[LS-39](https://linear.app/little-sprout-app/issue/LS-39/authgoogle-登入supabase-providerios-整合) 實作時二擇一，先不做也可以，走 Supabase OAuth＋ASWebAuthenticationSession 只要第 2 步。
5. 完成後在本票留 comment「provider 已啟用」＋ project-ref（非機密）即可 → Done。

## 驗收

* Supabase dashboard Google provider 顯示 Enabled。
* 本機 `supabase/config.toml` 不需改（本機測試走 `[auth.external.google]` 另由 [LS-39](https://linear.app/little-sprout-app/issue/LS-39/authgoogle-登入supabase-providerios-整合) 用 .env 注入 client ID，secret 走環境變數）。
