## 範圍

1. 找根因：`ChildrenStore` 在 `createChild`／`updateChild` 成功後是否更新了 published 的 children 陣列與 `avatarCacheBust`／簽名 URL 快取；列表 row 的 `id`／`Equatable` 是否讓 SwiftUI 認為沒變；簽名 URL 批次是否只在 tab 出現時重取。
2. 修法（最小）：儲存成功後同一個 store 內完成狀態更新（含 cache-bust key 與該 child 的簽名 URL 重取），列表立即重繪；不新增全域 refresh。
3. 測試：`ChildrenStoreAvatarTests` 補一案——`updateChild` 成功後 published children 的該筆 `avatar_url`／cache-bust 立即變更（mutation：拿掉更新 → 紅）；若涉及 view 層，UITests 加一步「儲存後回列表立即看到圖」（可用 accessibility label 帶版本）。
4. 模擬器實跑：owner 上傳頭像 → 返回列表 → 不切 tab 即顯示新圖（截圖）；互動段先 `supabase-lock.sh --hold`。

## (1) 原子寫入是否真的消除「兩次變值」——**通過**

逐行追 `updateChild`（換照片）與 `createChild`（建檔帶照片）兩條路徑上每個 await 點，看 `avatarURL(for:)`（＝`avatarSignedURLs[path]` ＋ `avatarCacheBust[path]` 兩者的函數）的值：

| 時點 | 舊碼（R2／R3） | 本 PR |
|---|---|---|
| upload 完成後 | **已寫新 cache-bust** → 值變 ①（新 bust ＋ 舊簽名 URL） | 只存進區域變數 `freshAvatarPath`，值不變 |
| `update_child` RPC（await） | 過渡態暴露給 SwiftUI 至少一次重繪 | 無變化 |
| `children = fetched`（await 後） | 路徑本身沒變（換照片）／nil→path 但尚未簽名（第一次加照片），值不變 | 同左，值不變 |
| 簽名 RPC（await） | — | — |
| `avatarSignedURLs = signed` ＋ `avatarCacheBust[fresh]`（同一同步區塊、中間無 await） | 值變 ②（新 bust ＋ 新簽名 URL） | 值變 **①（唯一一次）** |

- 兩個寫入之間沒有 await、同為 `@MainActor` 隔離、`ChildrenStore` 是 `@Observable`——SwiftUI 的重繪是另一個 main-actor transaction，不可能插進這兩行之間，所以兩次 mutation 對 view 是一次合併後的變更。**「一次上傳只變一次」成立。**
- `@MainActor` 隔離：`avatarCacheBust`／`avatarSignedURLs`／`avatarSignedURLsGeneration` 全部只在 `ChildrenStore`（`@MainActor`）內讀寫，`avatarURL(for:)` 也只在 body 求值時被讀，沒有跨 actor 面。
- **與世代守門的互動**：cache-bust 的寫入被放進 `if let signed, generation == avatarSignedURLsGeneration` 內——舊回應仍然一律丟棄（m2 守門沒被破壞，`ChildrenStoreAvatarTests.test_refresh_staleSignedURLResponseArrivesAfterNewerRefresh_...` 仍綠），代價見 i2。
- **與 LS-173 `AvatarLoadCoordinator` 的互動**：那是 PhotosPicker 選圖載入的世代守門（`CreateChildView`／`EditChildView`／`AvatarPickerLoader`），跟簽名 URL 這條路徑沒有共用狀態，兩者互不影響。

    let stub = StubChildAPIClient()
    let path = "fake/avatars/first.jpg"
    let child = makeChild(avatarURL: path)
    let uploadService = StubChildAvatarUploadService()
    stub.setListChildrenHandler { _ in [child] }
    stub.setSignedAvatarURLsHandler { _ in [path: URL(string: "https://example.test/signed?token=first")!] }
    let store = ChildrenStore(apiClient: stub, avatarUploadService: uploadService)
    _ = await store.refresh(familyID: familyID)
    let before = store.avatarURL(for: child)?.absoluteString ?? "nil"

    uploadService.setUploadAvatarHandler { _, _, _ in path }
    stub.setUpdateChildHandler { _, _, _, _ in }
    stub.setSignedAvatarURLsHandler { _ in [path: URL(string: "https://example.test/signed?token=second")!] }

    let seen = OSAllocatedUnfairLock<[String]>(initialState: [])
    let done = OSAllocatedUnfairLock<Bool>(initialState: false)
    // watcher 自己就是 @MainActor：`updateChild` 每次讓出主 actor 時它就取樣一次。
    // 取樣要在 withLock 之外讀（withLock 的閉包是 nonisolated，裡面呼叫 @MainActor 方法編不過）。
    let watcher = Task { @MainActor in
        while !done.withLock({ $0 }) {
            let sample = store.avatarURL(for: child)?.absoluteString ?? "nil"
            seen.withLock { $0.append(sample) }
            await Task.yield()
        }
    }

    let ok = await store.updateChild(
        childID: childID, name: "陳小安", birthday: Date(),
        currentAvatarURL: path, newAvatarImageData: Data([0x09])
    )
    done.withLock { $0 = true }
    _ = await watcher.value

    let after = store.avatarURL(for: child)?.absoluteString ?? "nil"
    let samples = seen.withLock { $0 }
    XCTAssertTrue(ok)
    XCTAssertGreaterThan(samples.count, 0, "watcher 一次都沒取到樣＝這條測試已退化成 no-op")  // 見 i4
    XCTAssertTrue(
        Set(samples).subtracting([before, after]).isEmpty,
        "一次上傳期間出現了過渡值：\(Set(samples).subtracting([before, after]))——`avatarCacheBust` 與 `avatarSignedURLs` 之間出現了 suspension point"
    )
}
