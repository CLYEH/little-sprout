## ui-designer.md「Pencil 已知限制」增補

1. **同一 execute 內 Create→Move**：節點與子樹靜默停止渲染、bounds 失真；Move 舊節點進「已損壞的新 frame」同樣中招。解法：建立與 Move 分兩次呼叫。
2. **Insert 在本 session 建立的節點完全不渲染**（Get 讀得到、截圖空白、Update 救不回）。解法：Replace 重建（strip id 的 addChild 程式碼在 [LS-38](https://linear.app/little-sprout-app/issue/LS-38/實驗第二輪軌-c-pen-軌-d-canvas-粉色調漸層各-5-輪對抗) 軌 C 第 3 輪 handoff）；副作用＝子孫全換新 id、操作後必重讀。
3. **width/height 在任何節點型別都不接受 $variable**（Update 靜默保舊值、Insert 靜默歸零；schema 寫接受是錯的——schema≠實作，可重跑實驗優先於文件）。可綁：gap/padding/cornerRadius/strokeWidth/fontSize/letterSpacing。交付規則：尺寸類 token 標「規格值」族並登記硬寫次數。
4. **execute 的 filePath 參數不會導向另一檔案**——一律作用於 currently active canvas editor（reviewer 帶 filePath 指向複本、探針仍寫進正式檔）。Reviewer 做破壞性實驗前必須先把正式檔 md5 記下、實驗後比對；或改在 [Pen.app](<http://Pen.app>) 另開複本成為 active 後再操作。

## 追加（[LS-46](https://linear.app/little-sprout-app/issue/LS-46/設計定稿合併c-基準使用者指定調整-designlittlesproutpen) R3-R6 發現，新版 [pen.dev](<http://pen.dev>) API）

* **API 面已變**：`get_app_state` 無參數；`execute` filePath 必填但仍裝飾性（不轉向 active editor）；無 `export_nodes`/`get_screenshot`，改 `execute` 內 `TakeScreenshot`/`Export`；先 `read_skill()`＋`execute.md`。
* `Insert()` 帶任何 nested `children`（含 frame）可能完全不渲染（資料正確）；可靠模式：`Insert()` 空殼 → `Replace()` 帶完整子樹。
* `Replace()` 對 `reusable:true` 元件的直接子節點一律 throw（繞道 Delete+Insert+Move）。
* `Update()` 靜默丟 `metadata`、`underline:true`、icon 的 width/height `$variable`；只有 `Replace()` 全節點寫得進。
* `Get()` 的 bounds/problems 快取失真（單屬性 Update/Move 後仍舊值）→ 掃描結果必用 `TakeScreenshot` 複驗；`ctx.problems` 只測父子裁切、對兄弟碰撞與橫列溢出無感 → 收工必跑絕對座標累加的全樹溢出掃描（reviewer 腳本在 scratchpad ls46r2/ls46r5）。
* Chromium 磁磟快取毒化 image fill（資產新增後仍棋盤格）：`pkill -9 Pen`＋清 `~/Library/Application Support/Pen/{Cache,GPUCache,Code Cache}`。
* `open -a "Pen" <path>` 可切 active editor（必 `get_app_state` 核對）；Pen 無視窗狀態會讓 MCP bridge 全數 62s timeout（需使用者 /mcp 重連或叫出視窗）；subagent 在 server 斷線期間 spawn 會缺 pencil 工具。
* 規則：AX/Stress 板必於基準畫面定稿後重建；handoff 不得以 bounds 數字當證據、每項附截圖。
