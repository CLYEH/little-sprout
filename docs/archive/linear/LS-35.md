## 描述

來源：PR #38 review 指出的既有問題（依手術式修改原則未在該 PR 修）。

`visual-reviewer.md` 的 verdict 詞彙混用：frontmatter 與「通過標準」段用 `REQUEST_CHANGES`，「迭代規定」段用 `ITERATE`（第 1、2 輪一律 ITERATE）。兩者是否同義未定義——orchestrator 依 COLLABORATION §7「設計稿須過 visual-reviewer 對抗審查」列做逐輪清點時，輪次記錄的標籤可能對不上。

修法：定義單一 verdict 詞彙表（建議：ITERATE＝退修、APPROVE＝通過，REQUEST_CHANGES 全部改為 ITERATE），全檔統一。走 hotfix 流程；低優先，可與下次 harness 變更共車。實務註：[LS-17](https://linear.app/little-sprout-app/issue/LS-17/storysign-in-with-appleemail-otp-登入)／[LS-31](https://linear.app/little-sprout-app/issue/LS-31/實驗design-canvas-管線-vs-pen-同-brief-三輪對抗比較) 兩軌審查記錄實際都用 ITERATE，統一方向從實踐取。
