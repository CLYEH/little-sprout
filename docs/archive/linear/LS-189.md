### B1（major）`LittleSprout/Features/Settings/ReportInboxView.swift:107` ＋ `:186-197` — 「這則沒問題」失敗時錯誤訊息永遠不會顯示

```swift
if let actionError, resolvingReportID == item.id {   // :107
...
Task {
    defer { resolvingReportID = nil }                // :190
    do { try await ...markReportResolved(...); items.removeAll {...} }
    catch { actionError = AppError.map(error) }      // :195
}
```
`defer` 在 do-catch 結束後才執行，且 `actionError = …` 與 `resolvingReportID = nil` 之間沒有 await 懸置點（同一個 MainActor 同步區塊），SwiftUI 只會渲染一次——渲染時 `resolvingReportID` 已是 nil，`:107` 的條件必為 false，錯誤列**一次都不會出現**。

**具體失敗情境**：Owner 在收件匣點「這則沒問題」，此時網路斷線（或 owner 剛被轉移出去 → `markReportResolved` 走 `SupabaseSafetyAPIClient.swift:118` 的 0 列 `AppError.rejected`）→ RPC throw → 卡片留在原地、沒有任何錯誤字、沒有轉圈、按鈕恢復可點。使用者只會覺得「按了沒反應」，且會誤以為只是手滑而重複點。諷刺的是本票特地做了 `markReportResolved` 的 0 列防線並為它寫了 mutation 測試（Mutation 2），但那個錯誤在 UI 端被吞掉。

**建議修法**：錯誤狀態改為與卡片綁定而不是與「進行中」綁定，例如把 `actionError: AppError?` 換成 `actionErrors: [UUID: AppError]`（鍵為 `item.id`），`:107` 改判 `if let actionError = actionErrors[item.id]`；或保留單值錯誤但另存 `failedReportID`。補一支走 `StubSafetyAPIClient`（見 B3）讓 `markReportResolved` throw 的測試釘住「錯誤字有顯示」。

### B2（major）`LittleSprout/Features/Timeline/DiaryDetailView+ContentActions.swift:61-65` — 封鎖成功後沒有觸發任何重抓，票文範圍 2 的「client 重抓」未落地

**具體失敗情境**：A 在 B 的日記詳情點「封鎖 B」→ 確認 → sheet 關閉 → **畫面原地停留在 B 的日記全文**（沒有 dismiss、沒有本地移除）；返回時間軸，B 的日記／照片全都還在，要使用者自己下拉重新整理才會消失。票文範圍 2 明文「封鎖後對方內容即時從時間軸消失（伺服器端過濾，client 重抓）」，QA 驗收第三條「A 封鎖 B → B 內容消失」在目前實作下必須加一個手動下拉步驟才會通過；實作者自己的 E2E 記錄也寫「時間軸下拉重新整理 →『還沒有回憶』」，正是這個缺口的證據。

### n1（minor）`LittleSprout/Support/PreviewSafetyAPIClient.swift:58-61` — `Dictionary(uniqueKeysWithValues:)` 在 `targetIDs` 有重複時會 trap

```swift
func fetchReportSnippets(targetType: ContentTargetType, targetIDs: [UUID]) async throws -> [UUID: String] {
    guard let reportSnippet else { return [:] }
    return Dictionary(uniqueKeysWithValues: targetIDs.map { ($0, reportSnippet) })
}
```
`ReportInboxAssembler` 傳進來的是 `reports.filter{...}.map(\.targetID)`——**同一則內容被兩個人檢舉時就會有重複 id**（正是 m1 當初設想的情境）。`Dictionary(uniqueKeysWithValues:)` 對重複鍵是 `fatalError`，不是覆寫。

**具體失敗情境**：日後有人在 harness 種兩筆同 `targetID` 的檢舉（例如要驗「同一則內容多人檢舉」的卡片呈現），UITest 會直接 crash 而不是斷言失敗，訊息是難懂的 `Duplicate values for key`。只影響 DEBUG（本檔整份包在 `#if DEBUG`）——production 走 `SupabaseSafetyAPIClient`，那邊字典是用回傳列（PK 唯一）建的，安全。所以 minor 不是 major。

**建議修法**：`Dictionary(targetIDs.map { ($0, reportSnippet) }, uniquingKeysWith: { first, _ in first })`。
