## 描述

[LS-20](https://linear.app/little-sprout-app/issue/LS-20/story相簿與照片上傳壓縮縮圖背景續傳) 的接力拆分：後端先行（純 DB／Storage，跳過 Design gate；上傳佇列與相簿 UI 等設計定稿）。與 [LS-38](https://linear.app/little-sprout-app/issue/LS-38/實驗第二輪軌-c-pen-軌-d-canvas-粉色調漸層各-5-輪對抗) 設計實驗零相依，可並行。

## Scope（migration＋測試）

1. **Storage bucket**（migration 建 `media` bucket，private；`insert into storage.buckets` 帶 file_size_limit 與 allowed_mime_types——HEIC/JPEG/PNG/MP4/MOV）。
2. **storage.objects RLS policies**（沿用 private.* STABLE SECURITY DEFINER 集合函式模式，禁逐列子查詢——PLAN §5）：
   * SELECT：同家庭成員可讀自家路徑
   * INSERT：成員且 `can_upload=true` 才可寫，且**路徑第一段必須等於自己所屬 family_id**（防跨家庭寫入）
   * UPDATE/DELETE：上傳者本人或 owner；軟刪除策略與 media 表對齊
3. **路徑規約** `{family_id}/{yyyy}/{mm}/{uuid}.<ext>`（取上傳時間）——寫進 policy 斷言（第一段 UUID 格式＝family_id）與 docs。
4. 測試（[run.sh](<http://run.sh>) 體系新檔）：跨家庭讀寫隔離、can_upload=false 被拒、路徑偽造（把別家 family_id 塞路徑第一段）被拒、owner 刪他人上傳、anon 全拒；**負向路徑演練**照慣例。
5. 簽名 URL 與 egress 防線（列表只載縮圖）屬 client 實作，本票只在 docs 記策略一行。
