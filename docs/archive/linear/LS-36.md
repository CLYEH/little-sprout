## 描述

來源：[LS-34](https://linear.app/little-sprout-app/issue/LS-34/harnessrunsh-全形括號在-bash-32-的-unbound-variable-bug-3) 新增的 `supabase/tests/65_fk_reverse_index.sql` 全 schema 列舉掃描，掃出 11 個 [LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies)～[LS-15](https://linear.app/little-sprout-app/issue/LS-15/db-硬化rls-auto-enable-收權sequencesfunctions-default-privileges) 遺留的外鍵缺反向索引（RI 檢查與反向查詢會退化成 seq scan；家庭級資料量下非急迫，屬效能衛生）：

* `albums.albums_created_by_fkey`
* `blocked_users` ×2
* `comments` ×2
* `content_reports.content_reports_reporter_id_fkey`
* `diaries.diaries_author_id_fkey`
* `families.families_created_by_fkey`
* `invites.invites_created_by_fkey`
* `media.media_uploaded_by_fkey`
* `reactions.reactions_user_id_fkey`

做法：一支 migration 補齊 11 個索引＋同 PR 把 65_ 的暫置白名單縮回空（該白名單有反向對照防過期，移除索引缺漏後不縮白名單會 FAIL——前饋反饋成對，天然滿足「migration 必附 tests 變更」gate）。正常 feature 流程；merge 後照 §6 雲端部署程序套用到 cloud。

判斷備註：是否每個 FK 都值得索引可在實作時逐一裁量（極少反向查詢的表可改列「有意不建」名單並附理由），不無腦全補。
