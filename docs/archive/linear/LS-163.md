## 關鍵設計決策與理由
1. **連結位置＝Email 按鈕與 Legal/Status 插槽之間（非插槽之上）**：插槽已有法務/狀態雙重用途（01/01c 放法務行、既有 01b 放狀態句），密碼連結是「第四種登入路徑」不是說明文字，放進 Actions 群組更符合語意，也避免與既有狀態插槽混淆。詳見 Notes 板「連結位置理由」節。
2. **密碼連結不用底線**：本輪實測發現 `underline:true` 在 `Insert()`／`Replace()` 建立文字節點時皆被靜默丟棄（比既有已知限制文件記載的「僅 `Update()` 丟棄」範圍更廣），改用 `$text-secondary` 色差＋44pt 熱區區分可點擊性（與票文規格「`$text-secondary`」一致，票文本身未要求底線）。此發現已記入 Notes 板，供後續其他票或 ui-designer 定義更新參考。
3. **密碼欄顯示/隱藏切換走 Replace() 改寫 instance 子節點**：`cmp/Text Field` 元件本身未改動，僅在 Password Field instance 的 Field Box 子節點路徑（`instanceId/v6YiYR`）整組換掉，新增 Toggle Wrap（icon+文字）。Email 欄與全稿其餘既有用法零回歸。
4. **P1c／P1d 兩種錯誤分開設計**：帳號密碼錯誤（欄框轉 danger）與網路錯誤（欄位中性）視覺語彙刻意不同——不能讓「連不上網路」讀成「你打錯密碼」。
5. **iPad 版不用 NavigationSplitView**：此畫面發生在登入完成前，應用程式尚無資料可放進側欄，改用置中 Auth Column（460pt，比照但寬於既有 04-iPad 294pt 側欄，因無需與照片並排）。
