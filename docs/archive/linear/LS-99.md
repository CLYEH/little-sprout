## 描述

## 來源

使用者 2026-08-25 demo 時問「一小時才 2 封？未來開放註冊怎麼辦」。

## 事實

* 本機：`supabase/config.toml` `[auth.rate_limit] email_sent = 2`（每小時，**全專案**而非每人），QA／demo 都被它卡（[LS-92](https://linear.app/little-sprout-app/issue/LS-92/story-文案小修otp-畫面還可以再試-0-次矛盾句ls-17-i-2429rate-limit-冷卻文案歸位i-3) rate-limit 測試、demo 取碼改走 Admin API）。
* **正式站**：Supabase 內建 SMTP 同樣是每小時 2 封、全專案共用，且**不能調高**；只有改用自訂 SMTP 後，dashboard Auth → Rate Limits 的 email 上限才可調（預設變 30／小時，可再提高）。
* 主登入是 Sign in with Apple／Google，不吃 email 額度；Email OTP 是長輩與審核員的備援——但 App Store 審核員一定會走 Email OTP，2 封／小時＝審核直接卡死。

## 要做（使用者決策＋操作；orchestrator 可代寫模板與文件）

1. **決策**：SMTP 供應商（Resend／Postmark／AWS SES 擇一；免費額度皆夠 MVP）與寄件網域（需你持有的網域，設 SPF／DKIM／DMARC）。
2. Supabase dashboard → Auth → SMTP Settings 填入供應商 host／port／user／**password（secret，不進 repo／Linear／對話）**、寄件人名稱「萌芽日記」。
3. Auth → Rate Limits：email 寄送上限提高（建議 ≥100／小時起，觀察後調）；OTP 驗證每 IP 上限維持預設。
4. Auth → Email Templates：Magic Link／OTP 模板改成含 `{{ .Token }}` 6 碼、長輩看得懂的文案（與 [LS-93](https://linear.app/little-sprout-app/issue/LS-93/harness本機-supabase-auth-自訂-otp-信件模板讓-inbucket-直接顯示-6-位驗證碼qa-不必走-admin) 本機模板同一份；orchestrator 出稿）。
5. 驗收：正式站用測試 email 連發 3 封 OTP 不被 429；信件在 Gmail／iCloud 不進垃圾桶（SPF／DKIM pass）；App 內 OTP 流程端到端通。
