## 描述

來源：使用者 2026-08-23 定案登入順序「Apple → **Google（新增）** → Email」（[LS-38](https://linear.app/little-sprout-app/issue/LS-38/實驗第二輪軌-c-pen-軌-d-canvas-粉色調漸層各-5-輪對抗) 實驗第二輪的設計定案之一）。原 M1 登入（[LS-17](https://linear.app/little-sprout-app/issue/LS-17/storysign-in-with-appleemail-otp-登入)）只有 Apple＋Email OTP，本票補 Google。

## Scope

1. Supabase Auth 啟用 Google provider（GCP OAuth client 建立、redirect URL 設定——dashboard 操作屬雲端設定，比照 §6 記錄操作與驗證證據；需要使用者的 GCP 帳號時先協調）。
2. iOS 端整合（Google Sign-In SDK 或 Supabase OAuth flow＋ASWebAuthenticationSession——實作時二擇一並記理由；深連結／URL scheme 設定進 project.yml）。
3. 登入畫面三鍵順序 Apple→Google→Email（設計稿由 [LS-38](https://linear.app/little-sprout-app/issue/LS-38/實驗第二輪軌-c-pen-軌-d-canvas-粉色調漸層各-5-輪對抗) 兩軌產出，實作依最終核可稿）。
4. 測試：登入流程 UI 測試＋帳號連結行為（同 email 的 Apple/Google/Email 三來源是否合併——Supabase 設定 confirm，行為寫進測試）。

## 驗收條件

- [ ] Google 登入在模擬器可完成全流程（QA 視覺驗收）
- [ ] 三鍵順序與核可設計稿一致
- [ ] 同 email 多 provider 的帳號行為有明確測試佐證
- [ ] Secrets（client id 等）不進 repo（走 xcconfig／環境注入，pre-commit 掃描涵蓋）
