## 設計

單一分派腳本 `scripts/hooks/pretool.sh`（讀 stdin JSON：`tool_name`／`tool_input`），規則表逐條比對，違規回 `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…指向規約條文"}}`；`pretool.test.sh` 以合成 stdin 正負自測（bash 3.2 `${name}`），掛 CI `rules` job。hook 載入需 `/hooks` 或重啟（PR body 註明；新 session 自動載入）。

**Fail-closed（使用者 concern 的核心）**：Claude Code 的 PreToolUse hook 只有 exit 2 才擋，其他錯誤是「印訊息但放行」——分派腳本外層 `trap`：任何內部錯誤（jq 缺、pattern 炸、檔案讀不到）一律轉為 deny（exit 2）並印原因。CI 自測含「腳本被弄壞時仍 deny」案例。

## 檢核層的誠實邊界（寫進 §7 盲區欄）

* 能防的：字面可辨的動作（H1–H3）——hook deny；伺服器端 required check 兜底（H1 的 force push 另有 GitHub 保護）。
* hook 本身失效：fail-closed 設計＋CI 自測；hook 未載入（本 session 改完設定未 `/hooks`）——PR body 必附本機 pipe-test 證據。

## 驗收
