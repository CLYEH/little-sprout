### 這份設計的靈魂是什麼／缺什麼

靈魂在於一個**克制到位的取捨**：Tab Bar 完全不碰 `$accent`，把每畫面唯一的實心配額留給「新增回憶」FAB（十條第 1／slop #15）。這是本輪最正確的決定，我會擋掉任何「用 accent 標選中」的提案。

但它缺的正是這個取捨的代價沒有被償付。文字拿掉了、accent 用不了，選中態的全部重量就只剩「形」與「明度」兩個非彩色通道——而**這兩個通道實測都沒有做功**：選中膠囊對軌道的背景對比淺色 1.354:1、深色 1.140:1（且方向在兩個主題間反轉），落影在深色是黑影壓黑底、貢獻趨近零；icon 只放大 1.18×。稿面與兩份 reference 卻寫著「對比與形狀變化要強」「三個維度疊加，缺一不成立」——**這是一句沒有量測的斷言，而量測反駁它**（slop #7 假驗證斷言；tokens.md 開宗明義「所有對比值為實測」）。

第二層缺口是語意：四顆 icon 沒有一顆帶「照片」或「家」的痕跡（`baby` 是唯一有人味的）。App icon 是 photo-stack（三張扇疊照片），Tab Bar 卻與它零押韻。遮住 logo，這排東西跟任何 2020 年代模板的浮動膠囊導覽差別只剩色票——我現在只寫得出 1.5 個記憶點（①不花 accent 的克制②粉調色票），距離 APPROVE 需要的三個具體記憶點還差得遠。

- **量測**：預設膠囊 64 高、cell 85.8×52，未選 icon **22**（`$icon-md`「一般圖示」）、選中 **26**（`$icon-lg`）。字形只佔膠囊高的 34%、cell 面積的 6.6%，其餘是死空間（見 `yXSht-bottom.png`，整條膠囊看起來是空的）。
- **為什麼是缺陷**：本票的起因是「最大字級會跑版」，解法是拿掉文字；但**預設字級的使用者只是失去了四個詞，什麼都沒換到**。iOS 原生 tab bar 是 49pt 高、25–28pt 圖示**外加**10pt 標籤；這裡 64pt 高、22pt 圖示、零標籤。這是通用 slop #4「字級怯懦」的 icon 版：唯一的尺寸訊號只有 1.18 階。
- **具體改法**：未選 **26**、選中 **32**。算式剛好收斂在節奏上——選中片 ＝ 32 ＋ 2×`$sp-tight` ＝ **44**（正好等於觸控下限，膠囊本身就是一個合格目標），52 − 44 ＝ **8** ＝ `$sp-label`，殘量落在節奏上（對照現況殘量 7，見 MN-1）。若 26/32 不想硬寫，就在 `tokens.md` 新增 `$icon-tab-md`／`$icon-tab-lg` 一對並註明它比 `$icon-md/lg` 大一階的理由（導覽不是「一般圖示」）。AX3 相應：40/48 維持，膠囊高改 **88**（76 − 60 ＝ 16 → 上下各 8，與預設同殘量）。

### MJ-2 四顆 icon 沒有一顆帶照片／家的痕跡，且與長輩最強的先驗（iOS 照片 app）相反

- **節點**：`QhkY2` gallery-vertical（時間軸）／`U6x04l` layout-grid（相簿）／`dVWf2` baby（寶貝）／`uMRQ8` settings（設定）。
- **兩個問題**：
  1. **與 app icon 零押韻**：本專案的識別是 photo-stack（三張扇疊照片）。把相簿從 `images` 換成 `layout-grid` 之後，全 app 唯一常駐的 chrome 上**一張「照片」都沒有**。這是 slop #10 的反面——不是拿圖庫 icon 冒充品牌，是讓圖庫 icon 把品牌語言整個擠掉。一個「長輩看孫子照片」的 app，導覽列看起來像檔案管理器。
  2. **映射與平台先驗相反**：iOS 照片 app 裡，**田字網格＝圖庫／所有照片、疊起來的長方形＝相簿**。本稿把「疊」給了時間軸、把「田字」給了相簿。70 歲第一次看到田字，最可能猜的是「所有照片」而不是「相簿」——這正是前提①「語意自明」要擋的。Notes 的選型理由只論證了「兩顆剪影不同」（成立），沒有論證「這顆剪影＝相簿」（不成立）。
- **具體改法**：讓 **相簿回到照片語彙**（`images`，或直接借 app icon 的三張扇疊剪影做一顆自家 icon——這會是這條 chrome 上唯一的品牌記憶點），**時間軸改用帶「一天一張、往下走」語彙者**（例如單張大卡＋上下留白的 `gallery-vertical` 保留，或 `rows-3`／日期感的語彙），差異軸從「照片 vs 非照片」改成「一條流 vs 一疊收藏」。若堅持現映射，Notes 必須正面回答「為什麼要跟 iOS 照片 app 相反」，而不是只說兩顆剪影不同。
- **可保留**：`baby`（`dVWf2`）與 `settings`（`uMRQ8`）在 AX3 匯出圖上都清楚可辨、語意自明，不要動。

### MJ-3 前提③ 有兩個洞：長按是硬約束禁止的手勢、選取狀態沒有 a11y 承載

- **(a) 例外二沒有非手勢替代路徑**。`elder-constraints.md` 同一節的硬約束是「不用雙擊、**長按**等進階手勢」，而 Large Content Viewer **只能靠長按叫出來**。LS-119 的例外一之所以被接受，是因為前提④明文要求「必須同時提供非手勢替代路徑」；**例外二把文字路徑 100% 押在一個硬約束禁止的手勢上，而且沒有承認這個衝突**。對一位不用 VoiceOver、也不會長按的長輩，全稿現在沒有任何地方能告訴他田字是什麼。
  - **佐證**：我掃了全部 119 個頂層節點——四個目的地只有**時間軸**有畫出來且 display 標題就叫「時間軸」（`yXSht` y70）；寶貝只有 `LS-47 / 09 寶貝管理`，**相簿與設定連畫面都還不存在**。
  - **改法**：例外二補第⑤條（比照例外一前提④）——非手勢替代路徑，最省事且已半成立的一條是「四個 tab 的目的地畫面一律以該 tab 名稱作 display 標題（時間軸／相簿／寶貝／設定）」，寫進 `motifs.md` 成為 Tab-root 畫面的硬規則，這樣點進去就是文字對照；或首次啟動一次性標示。條款寫死，不要留給未來的畫面票自由發揮。
- **(b) 選取狀態沒有 a11y 承載**：`metadata` 只有 `accessibilityLabel`，沒有 selected trait／value。文字沒了、對比又只有 1.14（BL-1），VoiceOver 使用者與弱視長輩是同一群人——`.accessibilityAddTraits(.isSelected)`（或 `accessibilityValue`）必須進 Notes。
- **(c) 標籤掛錯層**：四個 `accessibilityLabel` 標在 icon 葉節點（`QhkY2`/`U6x04l`/`dVWf2`/`uMRQ8`），可點的是 cell（`SXPya`/`k0VdrE`/`w91rB`/`ziWqY`）。照抄會做出「一個有標籤的裝飾圖 ＋ 一顆沒名字的按鈕」。metadata 移到 cell，icon 標 `accessibilityHidden`。

### MJ-4 「定案形態」只被畫出四分之一——沒有任何一張板顯示其他三顆被選中

- 11 個 instance 全在時間軸家族，全部是「時間軸選中」。`cmp/Tab Bar` 把選中寫死在第一顆（`BPtgR` 有 fill/shadow、另三顆是 `Indicator`），**相簿／寶貝／設定 被選中時長什麼樣，全稿沒有一處可看**。
- 驗收條件 1「有一個定案形態」與 2「全 app 只有一條規則」，在只畫出 1/4 狀態的情況下無法核銷。而且這三個未畫的狀態正是風險所在：`layout-grid` 的田字塞進圓形膠囊會比單一長方形擁擠得多；`settings` 齒輪外面再套一個圓，很容易讀成「處理中」的轉圈語彙。
- **改法**：在 `J2GxJV` 旁邊加一塊「四態對照」區塊——四個 instance 各選中一顆，預設＋AX3 各一排（8 個 instance），並把「同時只有一顆是 Selected Indicator」與**換選中要改哪些屬性**（fill／effect／icon w,h／icon fill，共 2 節點 × 4 屬性）寫成 Notes 的 override 配方。這塊本身就是驗收條件 1–2 的證據。
