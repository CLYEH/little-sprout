## 描述

## 來源

使用者 2026-08-25：「桌面上太多模擬器了吧，有開模擬器的任務結束後也要關掉」。當時 Booted 7 台（QA／ios-dev／push-gate 各自 boot 後沒關；[LS-83](https://linear.app/little-sprout-app/issue/LS-83/harnessdetect-simulator-以機型名選-destination多-worktree-併發-xcodebuild-test) 專屬機模式讓每個 worktree 再多一台）。orchestrator 已手動關閉除 demo 機外全部。

## 前饋（規約）

* `.claude/agents/ios-dev.md`／`qa.md`：任務結束（handoff 前）必 `xcrun simctl shutdown <UDID>`（自己 boot 的每一台），handoff「產出位置」加「模擬器已關：<UDID 列表>」。
* COLLABORATION §4／§6：push-gate 的 `xcodebuild test` 結束後關閉該次使用的專屬機（`KEEP_SIMULATOR=1` 可保留，供連續多次跑）。

## 反饋（機械）

* `scripts/gates/push-gate.sh`：`xcodebuild test` 之後 `xcrun simctl shutdown <UDID>`（成功失敗皆關；trap 確保中斷也關）；自測釘住接線（比照 ⑨）。
* `scripts/ops/patrol.sh`：新段「Booted 模擬器」——列出全部 Booted（名稱／UDID／boot 時間），>1 台且無在飛 UI／QA 票即 ⚠ 並印 `xcrun simctl shutdown <UDID>` 指令；`--brief` 也印；`patrol.test.sh` 加案例。
* 巡檢 cron 模板（§4-b）加一步：patrol 列出的 Booted 機若對應票已 Done／無在飛任務 → orchestrator 直接關（機械修復）。
* §7 加一列（盲區：使用者自己開的模擬器（demo）不在規則內，靠名稱 `demo-*` 豁免）。

## 驗收

* ios-dev／qa 各一次任務結束後 `xcrun simctl list | grep Booted` 只剩豁免機；push-gate 跑完專屬機為 Shutdown；巡檢在 Booted >1 時列出並印指令。hotfix 從 main。
