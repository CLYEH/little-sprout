## Findings（皆非 blocker／major）

**N1（minor, PLAUSIBLE）`scripts/hooks/background_bash_guard.py:76`（`BARE_AMP_RE`，用於 :116）：引號內的 `&` 也算「背景化」，會誤擋含 query string 的合法命令。**
`BARE_AMP_RE = r"(?<![&>])&(?!&|>)"` 只排除 `&&` 與 `>&`／`&>`，不做引號感知，所以字串字面裡的 `&` 一樣算數。實測誤擋（我自製樣本，非假設）：
- `for i in 1 2 3; do curl -s "https://abc.supabase.co/functions/v1/f?a=1&b=2"; sleep 5; done` → deny（`&` 來自 query string、`sleep` 在其後、keyword 命中 `supabase`）
- `curl -s "https://abc.supabase.co/a?b=1&c=2" | while read -r l; do echo "$l"; done` → deny
- `until gh api "repos/o/r/actions/runs?branch=main&per_page=1" | grep -q supabase; do sleep 20; done` → deny
- `sed -i '' 's/foo/&bar/' x.sh; bash supabase/tests/run.sh; sleep 1` → deny
失敗情境：QA／ios-dev 對本機 edge function 帶多個 query 參數輪詢時被擋，且 reason 說的是「背景化再等慣用形狀」，與命令實際做的事不符，容易讓 agent 誤判成環境壞掉。建議：`_idiom_hit` 對 `&` 位置沿用 `pretool_engine` 既有的引號追蹤（`strip_heredocs` 內已有 `q` 狀態機），或最低限度先剔除引號區間內的 `&`；再不然在 reason 補一句「若 `&` 只是 URL query 參數，請拆成兩條命令」。
未誤擋（同批實測，確認主流程安全）：`bash scripts/ops/promote-follow.sh 2>&1 | grep …`、`bash scripts/gates/push-gate.sh && sleep 5 && echo done`、`xcodebuild test 2>&1 | tee /tmp/x.log; sleep 2; grep …`、`bash scripts/ops/supabase-lock.sh -- supabase db reset`、`post-status.sh … --expect "$(gh pr view …)"`、以及 `until … ; do sleep 20; done`（無六個 keyword 時）。我也 grep 過 `docs/`／`.claude/agents/`：目前沒有任何規約教 agent 打會被 (b) 擋的命令。
