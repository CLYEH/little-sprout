## 前饋（規約）

## 反饋（機械）

* `scripts/ops/patrol-linear.sh`（或併入 `patrol.sh`）：GraphQL 查 team LS 的 open issues（id／title／state／labels／priority／createdAt／cycle／project／milestone／parent／blockedBy relations）＋當前 cycle；輸出：
  1. 狀態對照：Ready 無人接（無對應 worktree）、In Progress 無 worktree、QA 但 test 未含（對照 `git`）。
  2. Cycle 對帳 (a)–(d)。
  3. Lane 補位：每 lane 在飛數／上限（常數表在腳本頂端＋§5-b 同步）、候補（cycle 內 Backlog／Spec、priority→size→createdAt、blockedBy 全 Done 或 Canceled、有 project／milestone；跳過 [LS-96](https://linear.app/little-sprout-app/issue/LS-96/harness-待辦池常駐-reviewer-informational盲區補強純效率項先記在這裡滿足-high-以上條件才升獨立票)）、「待 Spec」以票文含「## 驗收」段判定。
  4. 開票結構 (a)–(e)。
  5. Booted 模擬器（[LS-100](https://linear.app/little-sprout-app/issue/LS-100/harness模擬器用完必關-ios-devqa-任務結束-simctl-shutdownpush-gate-測完關專屬機巡檢列出) 合併時）。
     `--json` 給程式；human 模式印「動作清單」（每行：`→ save_issue LS-n state=Ready cycle=1` 之類），orchestrator 逐行執行、不再自己查。
* 自測 `patrol-linear.test.sh`：stub `curl` 回固定 GraphQL JSON（正負案例：候補排序、blockedBy 未解、缺 size、cycle 外 active），bash 3.2；掛 CI `rules`。CI 無 token → 只跑自測。
* §7：[LS-75](https://linear.app/little-sprout-app/issue/LS-75/harnesslane-wip-上限backlogready-機械規則巡檢每輪補位票文-lane-標籤blockedby-關係)／77／79 相關列的「⚠️ 巡檢承載」改為「✅ patrol-linear.sh＋自測；動作執行仍由 orchestrator」。

### B1 · blocker · `scripts/ops/patrol_linear.py:97-101`（`CYCLE_ISSUES_QUERY`）——功能在真實 API 上 100% 不能用

Linear schema 的 `cycle(id:)` 參數是 `String!`，不是 `ID!`。實跑真 API：

```
✗ patrol-linear：GraphQL 錯誤：[{"message": "Variable \"$cycleId\" of type \"ID!\" used in position expecting type \"String!\".", ... "code": "GRAPHQL_VALIDATION_FAILED"}]
```
