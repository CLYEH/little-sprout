## 描述

## 來源

[LS-107](https://linear.app/little-sprout-app/issue/LS-107/taskls-18-iosa-首次進入三岔路建立家庭05邀請家人07owner-路徑)（Owner 路徑 iOS）實作時發現：`docs/API.md` 明定登入流程要 upsert `profiles`，但 repo 目前**沒有任何登入路徑做這件事**（Apple／Google／Email OTP 皆無）；`families`／`invites`／`join_requests` 的 RLS 與 RPC 依賴 `profiles` 存在。ios-dev 在 `createFamily` 前補了窄範圍 `ensureProfileExists` 解阻塞（PR #170），但 [LS-108](https://linear.app/little-sprout-app/issue/LS-108/taskls-18-iosb-輸入邀請碼06等待核准06ddeep-linkowner-審核清單加入路徑)**（加入路徑：**`request_join`**／**`list_join_requests` **讀 display_name／avatar）會再撞同一缺口**。

## 修法（後端為單一真相，client 不再負責）

* migration：`private.handle_new_auth_user()` SECURITY DEFINER trigger `after insert on auth.users` → `insert into public.profiles (id, display_name, avatar_url) values (new.id, coalesce(raw_user_meta_data->>'full_name', raw_user_meta_data->>'name', split_part(new.email,'@',1)), raw_user_meta_data->>'avatar_url') on conflict do nothing`；同 migration 回填既有 `auth.users` 缺 profile 的列。
* RLS：`profiles` 本人可 update（display_name／avatar），其他人依既有家庭關係可讀（維持現狀，只確認 trigger 不需要放寬）。
* `docs/API.md`：`profiles` 段改為「由 auth.users trigger 自動建立；client 只做 update」；登入流程段刪除 upsert 句。
* iOS：`SupabaseFamilyAPIClient.ensureProfileExists` 改為可移除（或保留為冪等保險但不再是必要路徑）——本票只改後端＋API.md；iOS 移除留給 [LS-108](https://linear.app/little-sprout-app/issue/LS-108/taskls-18-iosb-輸入邀請碼06等待核准06ddeep-linkowner-審核清單加入路徑) 順手。
* DB 測試（`supabase/tests/`）：新 auth user → profiles 列存在、display_name 推導正確；重複 insert 不炸；回填腳本冪等。

## 驗收

* `supabase db reset`（經 `scripts/ops/supabase-lock.sh --`）後 tests 全綠；CI db job 綠；`docs/API.md` 與 migration 對帳（api-contract gate）。
* 正式站：migration 由 orchestrator 依常設授權 `db push`（[LS-78](https://linear.app/little-sprout-app/issue/LS-78/harnesstestflight-前收回常設授權-migrate-to-production-改回需使用者允許機械-gate) 到期前）；push 後唯讀查 `profiles` 數＝`auth.users` 數。
* feature 從 development；backend lane；size:S。
