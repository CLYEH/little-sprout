## 問題

Pencil MCP `execute` 的 `filePath` 參數在**目標檔不是 Pen 目前 active document 時**，回傳的是 Pen 快取／active doc 的舊版內容，而非 `filePath` 指定路徑的實際檔案。[LS-108](https://linear.app/little-sprout-app/issue/LS-108/taskls-18-iosb-輸入邀請碼06等待核准06ddeep-linkowner-審核清單加入路徑) QA 對 qa-test worktree（test tip `1a12762`，含 [LS-111](https://linear.app/little-sprout-app/issue/LS-111/設計-chore07-邀請家人-角色選擇列一般成員只能看白話說明選中態ls-46-定稿只有單一產生鈕ls-107-以既有-token-暫拼) R13 合併版 3644 節點）的 `design/littlesprout.pen` 用 filePath 讀，三種路徑（原路徑／正規化等價／全新 scratchpad 複本）全回傳**舊版 3501 節點**；`git cat-file` 逐位元組確認磁碟檔本身是正確的 3644 版。當時 Pen active doc＝主 checkout（`main`＝v0.5.0，尚無 [LS-111](https://linear.app/little-sprout-app/issue/LS-111/設計-chore07-邀請家人-角色選擇列一般成員只能看白話說明選中態ls-46-定稿只有單一產生鈕ls-107-以既有-token-暫拼)，正是 3501 版）。

### F1 — `scripts/ops/pen-open.sh:341-343`（＋`379-384`）／major（觸發前提 PLAUSIBLE，程式路徑已確定性重現）

`--force-reload` 在 `pgrep` 找不到 Pen 主行程時走「跳過清場步驟，直接嘗試重開」，接著輪詢一致就印 `✓ pen-open：清場後 Pen 目前文件＝…` 並 **exit 0**——但沒有殺掉任何行程，服務中的還是同一個舊 renderer。這正好違反本模式唯一的存在理由（exit 0 ⇒ 全新 renderer 剛從磁碟讀過），而且是 fail-open 方向。

**失敗情境**：Pen 在跑（`pen interactive` 答得出 active 路徑）但 `pgrep -f 'Pen\.app/Contents/MacOS/Pen$'` 比對不到——主行程命令列帶了任何參數（`$` 錨點失效）、bundle 執行檔改名或搬家（版本升級）、pgrep 不在 PATH 皆可。此時 `pen-read.sh` 回 0，而 `qa.md`／`visual-reviewer.md` 的判準就是「exit 非 0 才停下」→ agent 拿到綠燈去讀一份可能停在舊 commit 的稿，**本票要治的病原樣復發，還多蓋一個 ✓**。

我用 `pen-read.test.sh` 同款 stub 環境（`pgrep` stub 成 exit 1、backup＝落地檔判安全、state 已是目標路徑）實跑 `pen-read.sh <root>`，輸出：`找不到 Pen 主行程（pgrep 沒有結果）——跳過清場步驟，直接嘗試重開` → `✓ pen-open：清場後 Pen 目前文件＝…` → `rc=0`。

**建議**：`force_reload=1` 時這個分支改 fail closed（exit 2，訊息「找不到 Pen 主行程，無法確認已換成全新 renderer」）；預設模式維持現狀（它的成功語意本來就只有「路徑一致」）。補一組自測。
