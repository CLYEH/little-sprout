## 反饋（機械）

### Blocker

**B1 — `has_real_history` 只分辨「動過／沒動過」，不分辨「做完／在飛」；同步一次就開刪**
`scripts/ops/cleanup-merged.sh:90-102`（判定）／`:196-204`（worktree 段）／`:237`（本機分支段）

失敗情境（已重現）：worktree 從**落後的**本機 `development` 切出（`git worktree add -b LS-901-sync <path> development`），agent 在寫下第一行程式碼之前先同步一次——`git pull --ff-only origin development`。reflog 因此多一筆 `pull ...: Fast-forward`，它不是 `branch: Created` 也不是 `checkout: `，`has_real_history` 立刻回 true；分支 tip 此時等於 `origin/development`，`is_merged_ref` 也是 true → `--apply` 直接：

```
→ 移除 worktree LS-901-sync（LS-901-sync，已併入且乾淨）
→ 刪除本機分支 LS-901-sync（已併入）
```

同樣會踩的日常動作還有 `git reset --hard origin/development`、`git rebase origin/development`、`git merge origin/development`——只要在第一個自有 commit 之前同步過一次，就從「尚未開工（受保護）」翻成「已併入（可刪）」。

這正是本票 comment 第 2 點宣稱修掉的那個 bug，修法只堵住「完全沒碰過」這一種形狀。自測 ⑬ `LS-13-fresh-never-started` 建完就不動它，所以永遠綠——測試給了不成立的信心（Rule 8）。

建議：`is_merged_ref` 為真時不能只問 reflog「有沒有動過」，要問「這條分支有沒有過自己的 commit」。可用 `git reflog show --format=%gs refs/heads/<b> | grep -qE '^commit'`（曾經 commit 過才算做過事），或直接改判「分支曾經被 push 過且該 push 的 tip 已併入」（`refs/remotes/origin/<b>` 存在或 reflog 有 `commit`／`commit (amend)`／`commit (initial)`），把「只同步過」排除在外。
