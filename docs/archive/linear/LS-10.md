## 描述

來源：[LS-9](https://linear.app/little-sprout-app/issue/LS-9/harness前饋反饋-gatesagent-model-政策qa-視覺驗收規約重構) merge review 的兩個不擋合併觀察（reviewer 實測確認）。

## Scope

1. **secrets gate 誤判逃生口**：`postgres(ql)?://user:pw@` pattern 會攔文件裡的示範連線字串，目前唯一出路是被規約禁止的 `--no-verify`。加明確標記（如同行含 `gate:allow-example` 即跳過該行），hook 與 CI 兩側同步。
2. **CI 逐筆 commit 驗證範圍**：目前以 head 分支名豁免 back-merge；若未來保護分支上出現不合規歷史 commit，會永久卡住所有含該 commit 的 feature PR。改用 `git log "$base_sha..HEAD" --not origin/main origin/development origin/test` 限縮為「不在任何保護分支上的 commit」。

## 驗收條件

- [ ] 紅綠測試：含 `gate:allow-example` 的示範連線字串放行；無標記者仍攔
- [ ] 紅綠測試：模擬保護分支含不合規 commit 時，feature PR 的 CI 不因歷史 commit 紅燈
- [ ] docs/COLLABORATION.md §7 對照表同步更新

備註：harness 票，依 §2 例外走 hotfix 流程。
3. **[detect-simulator.sh](<http://detect-simulator.sh>) 輸出含 OS 版本**（來源：[LS-5](https://linear.app/little-sprout-app/issue/LS-5/phase-0-1%E5%BB%BA%E7%AB%8B-xcode-%E5%B0%88%E6%A1%88%E9%AA%A8%E6%9E%B6swiftui-ios-17-swiftlint) handoff 觀察）：安裝多個 runtime 後同名模擬器有多台（如兩台 iPhone 17 Pro），目前只輸出名稱、由 xcodebuild 自行挑選，版本不可重現。讓腳本一併輸出並指定 OS。
4. **XcodeGen 漂移 gate 的 untracked 盲區**（來源：PR #6 review minor，實測重現）：`git diff --exit-code` 看不到 xcodegen 產生的全新未追蹤檔（如新 target 的 .xcscheme）。改用 `git add -A -- LittleSprout.xcodeproj && git diff --cached --exit-code` 或 `git status --porcelain` 判定。
5. **規約補記（docs/COLLABORATION.md §2）**：pull_request 的 workflow 定義跟著 head branch 走——harness CI 變更 back-merge 後，既有 open PR 需 `gh pr update-branch` 才吃得到新 gate（[LS-5](https://linear.app/little-sprout-app/issue/LS-5/phase-0-1%E5%BB%BA%E7%AB%8B-xcode-%E5%B0%88%E6%A1%88%E9%AA%A8%E6%9E%B6swiftui-ios-17-swiftlint) 實測，run 32560313234 vs 32560481798）。orchestrator 在每次 harness back-merge 後應對所有 open PR 執行 update-branch。
6. **rules job 的內容檢查（migration／design gate）限工作分支 PR**（來源：PR #10 promote 被 design gate 誤擋，實測）：promote（development→test、test→main）與 back-merge 的累積 diff 會重複觸發已在 feature PR 驗過的檢查（且 DESTRUCTIVE-APPROVED／Design: 標記不會自動携帶）。比照 commit-message 檢查，這兩段也改為僅對 feature|fix|hotfix head 執行。
7. **db job 的 SUPABASE_DB_URL 擷取加防呼呼失敗診斷**（來源：PR #15 review minor）：`VAR=$(... | grep ...)` 在 pipefail 下 grep 無命中會直接中止腳本且無訊息；改為 `|| true` 後接非空檢查與 ::error:: 訊息（reviewer 已附修法）。
8. **規約補列（docs/COLLABORATION.md §7）**：全域 function default privileges 收斂後的新慣例——「安裝 extension／新 schema 函式必須顯式 grant」（來源：PR #17 review F2）；機械面由 60_ 列舉式測試承載，規約面需補記。
