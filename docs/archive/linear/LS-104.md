### F1（blocker）`scripts/hooks/pretool.sh:336-341`（命令位置判定）— 前綴詞／shell 關鍵字／括號黏連可整條繞過 H1＋H2＋H3

「命令位置＝該段第一個非 `VAR=val` token」＋「只有命令位置等於 `git`／讀取動詞／`supabase`／`bash`／`sh` 才比對」是**精確字串相等比對**，於是任何夾在前面的詞、任何黏在 token 上的括號都會讓三條規則同時失效。實測繞成的類別（不列可直接複製的完整命令）：

1. **透明前綴詞**：`command` / `builtin` / `exec` / `env` / `sudo` / `nohup` / `time` / `timeout` / `stdbuf` / `caffeinate` / `script` 任一個接違規命令 → 三條規則全部 allow（舊版全 deny）。
2. **shell 關鍵字開頭的段落**：一行寫成 `if …; then <違規>; fi`、`for …; do <違規>; done`、`while …; do <違規>; done`、`case … in x) <違規>;; esac`、`! <違規>` → 該段命令位置是 `then`／`do`／`)`／`!`，allow。**這一類最要命**——`for f in a b; do bash supabase/tests/<那支腳本>; done` 是 agent 每天會自然寫出來的形狀，舊版擋、新版放。（註：`then` 後換行的多行寫法仍會被擋，只有寫成一行才漏。）
3. **括號黏連**：`(<違規>)`、`( <違規> )`、`{ <違規>; }`、`(cd x && <違規>)`、`(cd x; <違規>)` → 命令位置變成 `(supabase` 或末 token 變成 `reset)`，allow。
4. **路徑形式**：命令位置寫成絕對／相對路徑（`/usr/bin/git …`）、或前面加反斜線（`\git …`）→ 字串不等於 `git`，allow。
5. **間接執行**：`echo x | xargs git …`、`find … -exec git … \;`、先 `alias`／定義 function 再呼叫、`eval "<違規>"`（整串在引號內成為單一 token）→ allow。
6. **`$(...)` 內的關鍵字**：`$( if …; then <讀 .env>; fi )` 遞迴進去後同樣踩到第 2 點 → allow。

**失敗情境**：LS-88 這支 gate 的存在理由是「agent 在互動階段直接打出違規命令時攔下來」。合併後，只要違規命令前面多一個 `time`／`env`／`sudo`，或包在一行 `for … do … done` 裡，H1（`--no-verify`）、H2（讀 `.env`）、H3（裸跑 db reset／run.sh）**同時**失效。H3 尤其實際：多 worktree 並跑時漏一次裸跑就是把別人的 DB 洗掉（LS-70 原始事故）。

**建議修法**（關鍵在最後一條，光列舉前綴詞永遠列不完）：
- 取命令位置前先正規化 token：剝掉前導 `(`／`{`／`!` 與尾隨 `)`／`;`／`&`，再取 basename（`/usr/bin/git` → `git`）。
- 維護「透明前綴／shell 關鍵字」清單，遇到就往後再取一個命令位置（可重複數次、設上限）。
- **保守回退**：正規化後的命令位置若不在「已知安全動詞」白名單內（也就是我們不確定這段到底在跑什麼），該段退回舊版的整段字面比對再判一次。方向是寧可誤擋（誤擋面已被 LS-104 的 heredoc／引號剝除擋掉大半）也不要靜默漏放——這才是票文第 3 點「歧義即 deny」的精神，目前只套用在「切段失敗」，沒套用在「命令位置不認得」。

### F2（blocker）`scripts/hooks/pretool.sh:140-169` `strip_heredocs` — 假 heredoc 標記可以把後面真的會執行的命令整段吃掉

`strip_heredocs` 逐行掃 `<<[-~]?TAG`，**不管這個 `<<` 是不是在引號裡、是不是在 `#` 註解裡**。於是只要某一行的字串內容或註解裡出現 `<<TAG` 形狀，接下來到 `TAG` 那行為止的所有行都被當成「資料」剝掉，完全不進比對——但真實 shell 會照常執行它們。

實測三種形狀（引號內的 `<<TAG`、`#` 註解內的 `<<TAG`、單引號內的 `<<TAG`）都讓新版 allow、舊版 deny；我另外用真 bash 跑等價腳本確認中間那行**確實被執行**（印出 marker），bash 只是在結尾多報一個 `TAG: command not found`。

**失敗情境**：任何多行命令只要第一行的文字內容湊巧含 `<<某字`（寫說明、貼片段、產生文件），後續行的違規全部靜默放行；反過來也是最好用的刻意繞路——它比檔頭已揭露的盲區（寫進暫存腳本、`eval` 組字串）更直接：違規命令**原文就在 command 裡**，卻查不到。這是本票新增的能力，舊版沒有（舊版根本不剝 heredoc）。

**建議修法**：偵測 heredoc 起點前，先把「引號外的 `#` 之後」整段當註解移除，且只在引號外的 `<<` 才認 heredoc 起點（`tokenize` 已經有引號狀態機，兩者可以共用一次掃描）。更省事且方向正確的做法：被剝掉的 heredoc 內文另外保留一份，若 heredoc 起點的偵測有任何可疑（起點在引號／註解內、TAG 出現在行中而非行首指令位置），就把內文丟回做一次舊式整段字面比對——剝錯只會誤擋，不會漏放。

### F3（major）`scripts/hooks/pretool.sh:200-286` `tokenize` — 反斜線跳脫是 fail-open，不是 §7 宣稱的 fail-safe

`tokenize` 完全不處理 `\`（當普通字元累進 token）。實測 allow 而舊版 deny 的：旗標中間插反斜線（`--no\-verify` 這類，真實 shell 會還原成原旗標）、檔名前加反斜線（`\.env`）、`$'…'` 形式的檔名、以及 `bash -c "bash -c \"…\""` 這種巢狀跳脫引號——第四種特別值得注意：**`\"` 讓引號狀態機提前關閉、token 被切碎，遞迴那層就再也認不出違規**，不是變成 AMBIGUOUS。

§7 三列都寫「反斜線跳脫（如 `"a\"b"`）不認得，可能誤判引號邊界（**fail-safe 方向：更容易觸發歧義 deny，非漏放**）」——實測相反，是漏放。安全 gate 的盲區清單寫反方向比沒寫更危險（讀的人會以為這裡是安全的）。

**建議修法**：`tokenize` 加反斜線處理（引號外 `\X` → 逐字 X；雙引號內 `\"`／`\\`／`` \` ``／`\$` 依 shell 語意；單引號內不跳脫）。若不想做完整語意，至少在偵測到反斜線出現在引號內或緊接旗標字元時設 `AMBIGUOUS=1`——把文件宣稱的方向做成真的。

### F4（major）`scripts/hooks/pretool.sh:140-290` — tokenize／strip_heredocs 是 O(n²) 的 per-char bash 迴圈，每條 Bash 命令都要付

本機實測（同一台、取 2–3 次最小值），新版 vs main 舊版：

| command 長度 | 新版 | 舊版 |
|---|---|---|
| 50 B | 0.08 s | 0.21 s |
| 2 KB | 0.42 s | 0.14 s |
| 8 KB | 0.88 s | 0.05 s |
| 16 KB | 2.98 s | — |
| 32 KB | 11.25 s | — |
| 13.6 KB（heredoc 寫文件） | 3.66 s | — |

成長率 8K→16K→32K 是 3.4×／3.8×，明確二次（`${s:$i:1}` 逐字取＋`cur_tok="${cur_tok}${ch}"` 逐字累加，兩邊都是 O(n) per char）。**heredoc 內文並不便宜**——`strip_heredocs` 的 `out="${out}${line}"` 同樣是二次累加，13.6 KB 的寫文件命令就要 3.7 秒。

**失敗情境**：這支 hook 掛在每一個 Bash 工具呼叫前。LS-88 事故本身就是「用 heredoc 寫記憶檔／文件」——正是這類長命令。所有 agent（含平行跑的多個 worktree）每寫一次長文件就多付數秒，是全系統性的吞吐損失，且長度是使用者輸入可控的（32 KB 就 11 秒）。

**建議修法**：把逐字掃描搬進單次 `awk`／`python3` 掃描（本檔已經有 python3 備援依賴），或設長度門檻——超過 N KB 直接退回舊版的整段字面比對（快、且方向是寧嚴勿鬆），不要在 bash 裡跑 O(n²)。
