## 描述

來源：使用者 2026-08-31 反映——登入頁（WelcomeView）三顆按鈕只有「用 Apple 登入」是全英文，要求統一語言。

## 根因（已驗證，2026-08-31 orchestrator 於 main `170db4c`）

* Google／Email 鈕是自畫元件、文字寫死繁中（`AuthButtons.swift`）。
* Apple 鈕是官方 `SignInWithAppleButton`，文字由**系統依 app 宣告的 localization** 渲染，Apple API 不開放自訂文字（`AppleSignInButton.swift` 檔頭註解已說明，但該註解寫「依裝置語系」，少了「app 須宣告該語系」的前提）。
* 專案只宣告英文：`project.pbxproj` `developmentRegion = en`、`knownRegions = (Base, en)`、全 repo 無任何 `.lproj`、`project.yml` 無 localization 設定──所以**不論裝置語系**，Apple 官方鈕永遠 fallback 到英文。

## 修法（定案）

`project.yml` 的 `options` 加 `developmentLanguage: zh-Hant`（或等效設定，以 xcodegen 文件為準）→ `xcodegen generate`。app 全文案本來就是寫死的繁中，宣告 zh-Hant 為唯一語系後，所有使用者（含英文語系裝置）的 Apple 官方鈕都渲染中文（預期「使用 Apple 登入」），與另兩鈕一致；系統提供的其他 UI（photo picker、系統 alert 等）也會跟著變中文，同樣是想要的效果。

**刻意不加 en**：若同時宣告 en＋zh-Hant，英文裝置會變成 Apple 鈕英文／其餘寫死中文——回到同一個不一致。等未來真的做多語系（全文案進 String Catalog）再加。

## Scope

1. `project.yml` options 加 developmentLanguage → 重新 generate pbxproj（連動產物一起 commit，push-gate 會比對）。
2. `AppleSignInButton.swift` 檔頭註解修正：「由系統依裝置語系決定」→「由系統依 app 宣告的 localization 決定（本專案宣告 zh-Hant 為唯一語系）」。
3. 不改任何按鈕實作、不動版面。

## 驗收條件

- [ ] 模擬器實測（裝置語系 en 與 zh-Hant 各驗一次）：WelcomeView 的 Apple 官方鈕文字為中文，三鈕語言一致——附截圖
