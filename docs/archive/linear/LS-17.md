## 應修（major）

### A1 · `OTPVerificationModel.swift:77-105` —— `otp_expired` 不是「碼過期」，是「碼錯**或**過期」：B3 把最常見的打錯碼判成過期，還順手讓計次功能在正式環境變成不可達

```
1) POST /auth/v1/otp   {email: 全新信箱}                    → 200（碼剛寄出、還在有效期內）
2) POST /auth/v1/verify {email, token:"000000", type:email} → 403
   {"code":403,"error_code":"otp_expired","msg":"Token has expired or is invalid"}
3) 換 token "999999"                                        → 同上
4) 從未寄過碼的信箱 + token "123456"                         → 同上
```

GoTrue **蓄意**把「碼不存在／不相符」與「碼過期」壓成同一個 `error_code` 與同一句 `Token has expired or is invalid`（防帳號／碼列舉）。訊息裡的 `or is invalid` 就寫在回應裡。

**具體失敗情境**：長輩把 6 碼裡的一碼看錯（03b 這條路徑存在的唯一理由）→ 403 `otp_expired` → 畫面說「這組驗證碼已經過期了，請重新寄一組新的再試。」、`remainingAttempts` 停在 5 → 他去按「重新寄一次」，但 60 秒冷卻鎖著（後端 `max_frequency` 也擋）→ **他手上那組其實還有效的碼被說成過期，唯一有用的提示「碼不對，再看一次」永遠不出現**。R2 之前打錯碼會顯示「驗證碼不對，還可以再試 4 次」（R2 handoff 自己的模擬器紀錄就是這句）——**這是本輪引入的回歸**。
