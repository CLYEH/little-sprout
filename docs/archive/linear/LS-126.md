- **不會掉狀態**：`createMemoryButton` 無 `@State`，分支切換（旋轉／改字級）只是重建視圖，沒有狀態遺失或 `.task` 重跑問題。
- 軸向也對：`ViewThatFits(in: .horizontal)` 掛在 `header` 的 `.padding(.horizontal, 24)` 之內，被提議的寬度就是 345pt；候選 1 的 ideal 寬＝title＋Spacer minLength＋button（一般字級約 96.7＋8＋123.7≈228pt < 345 → 選同列），AX3 下漲到約 380pt > 345 → 退回堆疊。這正是預期行為。

**(2) 396 vs 220 的落差——是「量測沒生效」，不是字級上限、也不是我的估算錯**

結論：ios-dev 那次量到的 96.7／123.7 **是一般字級（content size L）的數字**，AX3 根本沒套用上去。三條證據：

1. **反推字級**：96.7pt ÷ 3 個漢字 ≈ 32.2pt／字，對應字級約 34pt（`.display` 的基準值，一般字級）；AX3 下 `.display` 走 `@ScaledMetric(34, relativeTo: .largeTitle)`，largeTitle 在 AX3 是 52pt，3 個漢字應該落在 148–156pt。按鈕同理：123.7pt ≈ icon 18＋gap 6＋4 個漢字×17≈65＋左右 padding 32 ＝ 121pt（一般字級），**與我上輪算的一般字級 ~124pt 吻合到 3%**；AX3 應該是 icon≈42＋6＋4×40≈152＋32 ＝ 232pt。
2. **機制**：`LittleSproutUITests/TapTargetMeasurement.swift:16` 的 `launch()` 內部自己 `XCUIApplication()` 後**無條件**寫 `launchEnvironment["UIPreferredContentSizeCategoryName"] = "UICTContentSizeCategoryL"`（檔頭註解寫明「固定一般字級」，#148 R1 F2 的刻意設計）。走這條 helper 就拿不到 AX3；在它之後改 `app.launchEnvironment` 也沒用（`launch()` 已經啟動）。本輪 CI 那行成功訊息也自己講了：「（一般字級 content_size large 量測）」。PR body 寫的 `UICTContentSizeCategoryAccessibilityXL` 字串本身是對的 AX3 值，問題出在它有沒有真的生效。
3. **排除字級上限假說**：`AppFontToken.maxScaledSize`（`Typography.swift:62-67`）只有 `.code` 是 72pt，`.display`／`.body` 等一律 `nil`＝不設上限。所以「`maxScaledSize` 上限生效」在原始碼層面就不成立。

所以：**AX3 溢出風險仍然未被證實也未被推翻**，我上輪的估算沒有被推翻。`ViewThatFits` 保留是對的（零成本、用不到時不影響現有排版）。給 QA 的具體檢查點也因此換方向：不是「確認 AX3 同列沒溢出」，而是**「AX3 下應該看到堆疊兩列；一般字級應該看到同列 space-between」**——兩個字級各看一次就能同時驗證 ViewThatFits 的兩個分支都對。

**(3) harness 新 case 真的量到 pill 了；exemptions 改動沒有弄壞其他行**

- **真的量到**：`tap-target-check.sh` 跑的是 `-only-testing:LittleSproutUITests`（不縮到特定 class），`testTimelineViewDefaultState` 在既有的 `TapTargetGateTests.swift` 裡（沒有新檔案，所以 XcodeGen 漂移檢查也綠），必然被執行；本輪 CI 的 gate 步驟走的是**實跑分支**（PR diff 含 `Features/`，沒有進「略過」分支），耗時 3m24s 且 exit 0。而該測試要綠必須同時滿足兩件事：`assertScreenRendered` 找到 `app.buttons["新增回憶"]`（否則 10 秒逾時 XCTFail），以及 `violations()` 對畫面上每顆 Button 的 `frame` 都 ≥44×44（否則列出 `TAP-TARGET-FAIL`）。**所以我上輪只能用「SwiftUI 版面語意」擔保的「`minHeight` 撐出 44pt 命中區」，現在是模擬器實測過的事實**——這是本輪最有價值的一項。

**(4) `accessibilityHidden(true)` 不影響 VoiceOver 讀出「新增回憶」——正確，而且是必要的**

Button 的 accessibility 是把 label 子樹合併成單一元素；把純裝飾的 `Image(systemName: "plus")` 標成 hidden 之後，合併 label 只剩 `Text("新增回憶")`，VoiceOver 讀出來就是「新增回憶，按鈕」，資訊零損失（加號的語意本來就已經由文字承載，同 `PhotoCardView` 影片徽章的既有先例）。反過來說這一步是**必要**的：`TapTargetGateSentinel.element(in:)` 用的是 `app.buttons[label]` **精確比對**，icon 不隱藏時 SF Symbol 的預設描述會併進合併 label，字串就對不上、sentinel 會逾時。本輪 CI 綠＝這顆 Button 的 label 確實正好等於「新增回憶」，等於同時驗證了這一項。
