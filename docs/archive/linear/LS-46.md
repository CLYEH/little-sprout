## Pencil 新版 API 發現（供 LS-44 更新）

- `filePath` 參數確認**仍是裝飾性**——刻意打錯路徑（`/Users/clyeti/...`）`execute` 仍正常對已啟用的 editor 生效，不報錯也不切換檔案，需持續用 `get_app_state` 核對真正 active editor。
- `Replace()` 對 `reusable:true` 元件的**直接子節點一律拋錯** `TypeError: Cannot read properties of undefined (reading 'type')`，與目標節點型別無關（測過 path/rectangle/text 皆同錯）；對一般畫面節點（非元件子節點）`Replace()` 正常運作。繞法：`Delete` 舊節點＋`Insert` 新節點到元件＋`Move` 回原索引；若有 `ref` 實例在 `descendants` 覆寫該子節點，覆寫 key 需同步換成新節點 id（可用完整型別替換覆寫，如 loading 態 spinner）。
- `get_app_state` 新版不吃任何參數（呼叫時帶參數會被忽略/不需要）。
- `layoutPosition:"absolute"` 在一般 flex（非 `layout:"none"`）容器內可正常疊加子節點且不影響父層 `fit_content` 尺寸計算——比 `layout:"none"` 手動定位更省事，適合做規線/浮水印疊加。

- **`Insert()` 對新建葉節點（text／icon）有位移 bug**：新插入的 text/icon 節點的 y（有時 x）座標會被錯誤地大幅偏移（本輪多次重現，偏移量隨情境變化、非固定常數），導致內容視覺上位移出容器甚至完全看不到，但 `ctx.bounds` 與 `TakeScreenshot` 對此一致（不是快取問題，是真實渲染錯誤）。**繞法**：改用 `Copy()` 複製既有同類節點再 `Update()` 內容/樣式；或用 `Replace()` 一次性帶完整巢狀 `children` 樹（本輪測試 `Replace()` 產生的巢狀子節點定位正常，只有裸 `Insert()` 會出這個 bug）。

- **`descendants` 覆寫是 merge 不是 replace**：`Update(refId,{descendants:{}})` 不會清除既有覆寫鍵；要清除某個覆寫，必須明確把該 key 的值改寫成目標內容（無法用空物件重置）。但如果被覆寫的目標 descendant id 已從元件定義中刪除，覆寫鍵會自動被裁剪掉（不是 merge 保留）。

## 新發現：Pencil `Insert()` 帶巢狀 children 的隱形渲染 bug（供 LS-44）

本輪重現且定位到比 R3 記錄更廣的一個 bug：**`Insert()` 只要一次帶入巢狀 `children` 陣列（不只是裸葉節點，frame 帶 children 也一樣），該節點會渲染成完全空白／不可見**，即使 `Get()` 讀回的資料結構完全正確（children 都在、屬性都對）。R3 記錄的「只有裸 Insert() 會出這個 bug」範圍界定過窄——本輪在 06b/06c 重排（`Insert(parent,{...,children:[...]})` 一次建好 Head Group）與 Handoff Notes 新增條目（`Insert(FqoFZ,{...,children:[...]})`）都各自重現一次，兩者都不涉及 Move()。**確認的唯一可靠模式**：`Insert()` 只用來建**空殼**（不帶 children 或只帶 1-2 個基本屬性），內容一律用 `Replace()` 一次性帶完整巢狀 `children` 樹寫入——這個模式本輪測試數十次全部正確渲染，零失敗。建議 LS-44 的 CLAUDE.md 條目改寫成「**Insert() 只建空殼，Replace() 才能安全帶巢狀內容**」，取代「只有裸葉節點有 bug」的舊表述。

延伸副作用：多欄並排佈局（F16 壓測板 3 欄）若連續兩次 Copy() 到剛建立的空殼欄位，中間那欄的 `Get()` bounds 會回報與第一欄相同座標（視覺上可能重疊或消失）——同一批節點反覆 fresh call 都拿到一致但錯誤的舊值，跟 R3 記錄的 bounds 快取失真同源；**唯一排除法是刪除重建該欄並立即截圖複驗**，不能只靠再讀一次 bounds。
