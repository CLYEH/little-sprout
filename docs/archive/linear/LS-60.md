## 描述

## 現象

`.claude/agents/merge-reviewer.md` 與 `dead-code-sweeper.md` 的 `tools:` 明列 `Bash, Read, Grep, Glob`，不含任何 `mcp__linear__*`。結果：orchestrator 每次要求「用 linear MCP 讀票文／寫回 Linear comment」都做不到——reviewer 只能從 commit/PR body 間接佐證 N 編號對應（[LS-55](https://linear.app/little-sprout-app/issue/LS-55/ios-基礎層收尾-minorspr-63-r2-n1-n9initialsession-離線抹-nil快取非同步測試ls999-測試死碼) R1 明示「未審範圍：票文未讀」），comment 由 orchestrator 代貼。這違反「Linear 是唯一任務狀態來源」：審查依據不是票文本身。

## 修法

兩份 agent 定義的 `tools:` 加 `mcp__linear__get_issue, mcp__linear__list_comments, mcp__linear__save_comment`（sweeper 只需前兩者）。不放 `save_issue`（審查者不得改狀態）。

## 驗收

* 派一次 merge-reviewer 讀 [LS-55](https://linear.app/little-sprout-app/issue/LS-55/ios-基礎層收尾-minorspr-63-r2-n1-n9initialsession-離線抹-nil快取非同步測試ls999-測試死碼) 票文並寫一則測試 comment（隨後刪除或標記）——證明工具可用。
* COLLABORATION §1 model／tool 政策段補一句：審查類 agent 具 Linear 讀＋comment 寫、無狀態變更權。

## 分支

harness → `hotfix/LS-<n>-*` 從 main 切、PR 回 main、back-merge。orchestrator 自做（harness 例外）。
