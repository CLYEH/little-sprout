## 描述

## 來源

使用者 2026-08-25 問「Linear 能不能加 Sprint」→ 已在 Team settings 開啟 Cycles（1 週、自動把 active 票加進當前 cycle）。Linear 產生 Cycle 1（2026-08-31 起）／Cycle 2。使用者要求「前饋和反饋都要有」。

## 分工原則

Cycle 回答「這週要達成什麼」（方向盤，使用者每週唯一固定決策點）；lane 規則回答「下一張做什麼」（引擎）。Cycle 為主軸：lane 補位只從當前 cycle 取票。

## 前饋（COLLABORATION 新 §5-c「Cycle」＋ CLAUDE.md 一行 ＋ §4-b 巡檢模板）

* F1 Cycle＝1 週、無 cooldown。「規劃 cycle」＝當前 cycle；無當前 cycle 時＝最早的 upcoming cycle。
* F2 規劃：cycle 開始當天首次巡檢，orchestrator 產出提案——依 milestone 順序＋各 lane 上限×可用天數估算，含上一 cycle 滾入票——以 `save_document`（project「Phase 1」底下「Cycle N 規劃」）貼出並在晨報同步；使用者回「同意」或調整一次即核可。核可前 orchestrator 只可把「滾入票＋在飛票」放進 cycle。
* F3 派工來源：lane 補位只從當前 cycle 的 Backlog 取（priority → createdAt）；該 lane 在 cycle 內無票 → 取 cycle 外最高優先**並加入當前 cycle**（scope 增加在 cycle 圖可見）＋巡檢紀錄一行。
* F4 臨時票（事故 harness、review 衍生小票）：開票即帶 `cycle`＝當前 cycle，不等規劃。
* F5 結束：未完成自動滾入（Linear）；結束後首次巡檢貼「Cycle N 回顧」（完成／滾入／scope 變化／本週各票 retro 改善項彙整）到同一 Document；晨報改為 cycle 週報。

## 反饋（機械）

* G1 PreToolUse hook `mcp__linear__save_issue`（與 [LS-77](https://linear.app/little-sprout-app/issue/LS-77/harness開票結構-gate-open-票必有-projectphase-票必有-milestonetask-必有) 同一支 `scripts/gates/linear-issue-check.sh`，兩票可合併實作）：`state` 為 `Ready`／`In Progress` 且未帶 `cycle` → `permissionDecision: deny`（派工必進 cycle）；建票即 Ready／In Progress 同規則。Backlog 票不要求 cycle。正負自測。
* G2 Linear 原生「自動把 active 票加進當前 cycle」已開：覆蓋使用者在 UI 手動改狀態的路徑（盲區補強）。
* G3 巡檢步驟「Cycle 對帳」（§4-b 模板＋cron prompt）：`list_cycles` 取當前（或最早 upcoming）cycle → (a) active 票（Ready／In Progress／In Review／QA／Design／Spec）不在該 cycle → 列出並 `save_issue cycle` 補加；(b) cycle 內 Backlog 票 blockedBy 未解 → 列「規劃錯誤」；(c) cycle 第 2 天仍無「Cycle N 規劃」Document → 列「未規劃」；(d) 剩 <24h → 提醒回顧。任一非空不得回「無異常」。
* G4 §7 對照表兩列：前饋 F2–F4／反饋 G1＋G3；盲區明寫：MCP 無建 cycle 工具（cycle 日期只能在 UI 調）、Document 核可靠人回覆。

## 驗收

* hook 自測：`state: Ready` 無 cycle → deny；有 cycle → allow；`state: Done` 無 cycle → allow。
* 一次巡檢實跑印出 cycle 對帳段（四類皆空）。
* 第一個 cycle 的規劃 Document 存在且使用者核可記錄在 Document 內。
