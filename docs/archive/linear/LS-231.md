## 範圍

1. `.github/workflows/ci.yml`：`ci`／`ci-ipad` 兩 job 的 `xcodebuild test` 步驟之後加 `if: failure()` 的 `actions/upload-artifact`，上傳 `*.xcresult`（`-resultBundlePath` 固定路徑；`retention-days: 3`；名稱含 job 與 run attempt）。
2. `scripts/gates/tap-target-check.sh`（或 CI 呼叫它的 wrapper）：摘要段除「本輪所有失敗測試」測試名外，再印每支失敗測試的第一行 assertion 訊息（`error:` 行／`XCTAssert… failed` 行，`xcresulttool` 或 log grep 皆可），並印 artifact 名稱提示。
3. `docs/COLLABORATION.md` §4-b「`rules` job 紅先看 ✗」規則旁補「`ci`／`ci-ipad` 紅先 `gh run download <run-id> -n <artifact>` 取 xcresult 看失敗行，再決定 rerun 或修」；§7 對照表加一列。
4. 驗證：對一個刻意失敗的 UITest 分支（或用既有 fixture）跑一次 CI，確認 artifact 出現且 `xcrun xcresulttool get --path` 可讀；push 成功時不上傳（`if: failure()`）。
