## 描述

PLAN Phase 1-2。**UI 票：需 Design gate**（首次進入三岔路：建家庭／輸入邀請碼／deep link）。

## Scope

* 建立家庭（走 [LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies) 已修好的 INSERT+RETURNING 路徑）
* 邀請碼／連結：產生（期限＋次數上限）、加入 RPC（SECURITY DEFINER——[LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies) 遺留：invites 目前僅 owner 可讀，加入需 RPC）
* **一併收斂 family_members_insert policy**（[LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies) review m2 債：owner 可繞過邀請直塞成員）

## 驗收條件

- [ ] 第二測試帳號經邀請碼加入成功；過期／超次數的碼被拒
- [ ] **全新帳號無任何邀請碼能自建家庭並邀請他人**（§9-C5 上架硬要求）
- [ ] 收斂後 owner 無法繞過邀請直接 INSERT 成員（RLS 測試）
- [ ] 加入 RPC 有 RLS 測試（migration gate）

## 使用者核定（2026-08-22）：邀請碼＋管理員審核

* 加入流程改兩段：輸入有效邀請碼 → 產生待核請求（非直接入家）→ Owner 收通知、見申請人資訊 → 核准才寫入 family_members（拒絕則丟棄，無殘留權限）。
* 審核為家庭級開關，**預設開**；關閉時碼驗證後直接加入。
* 理由：外洩碼最多讓陌生人出現在待核清單被人眼攔下；優於 slug＋密碼方案（長命低熵、同通道同因子、slug 可枚舉）。

## 驗收條件（審核增補）

- [ ] 輸碼後進入「等待核准」態；核准前看不到任何家庭內容（RLS 測試）
- [ ] Owner 可核准／拒絕；拒絕後申請人無殘留權限
- [ ] 審核關閉時直接加入；開關僅 Owner 可改
- [ ] 待核請求的 RLS（申請人僅見自己、Owner 僅見自家）＋RPC 測試
