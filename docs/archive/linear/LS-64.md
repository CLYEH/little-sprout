### Findings

**F1 — minor — `supabase/tests/87_comments_reactions_notifications.sql:1088`（anon DO 區塊）：六句斷言實際上退化成一句事實**

`init_schema.sql:16-17` 只 `grant usage on schema private to authenticated`，anon 沒有 schema USAGE，所以名稱解析階段就先擋掉，`private.` 底下**任何**名稱都回 42501「permission denied for schema private」。實測對照：

- anon 呼叫 `private.this_function_does_not_exist_xyz()` → **42501**（綠）
- authenticated 呼叫同一句 → 42883 undefined_function（紅）

**具體失敗情境**：日後六支函式被改名／刪除／改簽名，或有人只 `grant execute … to anon` 而沒動 schema USAGE——anon 這半段**在上述每一種情況下都維持綠**。它真正鎖住的只有「anon 沒有 schema private 的 USAGE」這一件事，而不是六支函式各自的 grant。

`87_:1005-1008` 的註解已誠實揭露這件事（「`anon` 另外可能先卡在 permission denied for schema private」），M4 也只宣稱對 authenticated 做過 mutation，所以**沒有虛報強度**，因此只列 minor。但收尾的 `raise notice`「anon 直呼六支 … 皆 42501」讀起來比實際保證強。

建議（非必要）：anon 半段改成斷言訊息形狀（`sqlerrm like '%schema private%'`）把「這裡驗的是 schema 層」講死，或收成一次呼叫＋一句註解說明；authenticated 半段維持原樣即可（那半段是真的有效）。
