## 描述

[LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies) 合併後的部署步驟。**需使用者協助**：supabase MCP 已依規約鎖 `read_only=true`，部署時需暫時解鎖（或提供 `supabase link` 的 DB 密碼給 CLI 路徑），完成後恢復唯讀。

## Scope

1. 將 `supabase/migrations` 套用到雲端專案（mzkkkzbiejgvhwjyiokf）。
2. `\ddp` **覆核 default privileges**（PR #4 reviewer 點名：M4 的 `alter default privileges` 只影響「由執行角色建立」的物件；真實 Supabase 上可能同時掛在 `postgres` 與 `supabase_admin` 名下，必要時對每個 owner 角色補 `for role <role>`）。這是唯一「本地測試綠、正式環境仍可能 no-op」的修復，**必須實際執行**。
3. 雲端跑一次 `supabase/tests/run.sh` 等效驗證（隔離／owner 不變量／授權斷言），或至少 60_/70_ 的授權斷言。
4. `get_advisors`（security）掃一次，處理發現項。
