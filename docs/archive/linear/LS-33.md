## 描述

[LS-18](https://linear.app/little-sprout-app/issue/LS-18/story建立家庭與邀請加入) 的多 agent 接力拆分（§5 規約）：後端先行（純 DB，跳過 Design；UI task 等 design gate）。依使用者核定的「邀請碼＋管理員審核」spec。

## Scope（migration＋RPC＋測試）

1. `join_requests` 表（family_id、invite_id、applicant_id、status: pending/approved/rejected、時間戳）＋RLS（申請人僅見自己、Owner 僅見自家）
2. `families.require_approval`（預設 true，僅 Owner 可改）
3. RPC（SECURITY DEFINER、search_path 收斂、逐支顯式 grant）：
   * `create_invite(role, expires_at, max_uses)`（Owner）
   * `request_join(code)`：驗碼（有效期/次數）→ 審核開＝建 pending 請求；關＝直接入家。**used_count 消耗時點與併發正確性**（兩人同時用最後一次額度）要處理並測
   * `approve_join(request_id)`／`reject_join(request_id)`（Owner；approve 寫入 family_members）
   * `withdraw_join(request_id)`（申請人撤回）
4. **收斂 family_members_insert policy**（[LS-6](https://linear.app/little-sprout-app/issue/LS-6/phase-0-2supabase-專案schema-migrationrls-policies) review m2 債：owner 不得繞過邀請直塞成員——唯一寫入路徑是 RPC）
5. 測試（[run.sh](<http://run.sh>) 體系）：驗收條件全數＋併發（used_count 競態、同一申請人重複申請、approve/reject 競態）＋mutation test

## 驗收條件（承 [LS-18](https://linear.app/little-sprout-app/issue/LS-18/story建立家庭與邀請加入)）

- [ ] 核准前申請人看不到任何家庭內容（RLS 測試）
- [ ] 過期／超次數碼被拒（分開的錯誤碼供 UI 分文案）
- [ ] 拒絕後無殘留權限；審核關閉直接入家；開關僅 Owner
- [ ] owner 無法繞過邀請直接 INSERT 成員
- [ ] CI db job 綠（migration gate 自動把關）
