### m7（minor）`privacy-policy.md:176`「**單獨**上傳的照片與影片」— 一個詞造成的漏揭露：附在日記裡的照片同樣留著、且同樣還顯示在時間軸

§8 ① 先寫「您撰寫的日記、相簿與留言標記為刪除並**停止對家庭成員顯示**」，緊接著 ② 寫「您**單獨**上傳的照片與影片會保留」。「單獨上傳」在中文最自然的讀法是「沒有附在日記／相簿裡、單獨上傳的那些」——照這個讀法，讀者會推論「附在我日記裡的照片隨日記一起看不見了」。**實際不是**：

- `triggers.sql:141-169` `feed_sync_media()` 對**每一列** `media`（`deleted_at is null`）都建一筆 `kind='media'` 的 `feed_items`，與它有沒有 `diary_media` 連結無關；repo 內沒有任何地方把「已連到日記的 media」從 feed 排除（我 grep 過 `feed_items` 的全部 delete／filter 路徑）。
- 日記軟刪只會刪掉 `kind='diary'` 那一筆 feed item（`diaries_write_path_and_timeline.sql:346`），`media` 列與它的 feed item 原封不動。
- App 端 `MediaUploadService.insertMediaRow()` 是一般 INSERT（日記附照走同一條路），`get_family_timeline` 回傳全部 feed_items，`TimelineContentAssembler` 也沒有去重。

⇒ 帳號刪除後，**所有** `uploaded_by` 是您的照片都留著並繼續顯示，不只「單獨上傳」的。

**具體失敗情境**：使用者刪帳號前只刪掉「相簿頁看得到的散照」，以為日記裡的照片會跟著日記一起消失；實際上那些照片仍逐張留在家庭時間軸上。

**建議修法**：刪掉「單獨」二字，或改為「您上傳的照片與影片（**包括附在日記或相簿中的**）」。

Apple App Privacy 的**分類（category）**是「識別碼 Identifiers」，**資料類型（data type）**才是「使用者 ID User ID」與「裝置 ID Device ID」。現在表裡 `:237`「識別碼 Identifiers ｜ 使用者 ID」與 `:239`「裝置 ID Device ID ｜ 推播裝置代碼」兩列並排，等於把同一個分類拆成兩列、其中一列的分類欄填了資料類型。

**具體失敗情境**：照這張表填 App Store Connect 時，填表人會在分類清單裡找不到叫「Device ID」的分類而卡住，或誤以為要勾兩個不同分類。

**修法**：兩列併成一列——`| 識別碼 Identifiers | 使用者 ID；裝置 ID（推播裝置代碼 device token） | App 功能 | §2.1、§2.5 |`。（R3 新加的「與您的帳號連結」與表格前言「皆屬『與您連結的資料（Data Linked to You）』」重複，可留可刪，不是問題。）
